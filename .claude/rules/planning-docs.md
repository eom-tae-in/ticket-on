# 기획 문서 규칙

- 모든 기능 명세는 `docs/` 아래에 있다. 기능을 구현하기 전에 해당 문서를 읽는다.
- 전체 관계도는 `docs/14-domain-model.md`다. 무엇이 무엇을 가리키는지(티켓 → 회차·좌석 등)는 여기를 따른다.
- 핵심 모델은 `docs/02-event-model.md`(날짜·회차·구역·블록·좌석)와 `docs/07-ticket.md`(티켓·QR)다.
- 문서마다 "왜 그렇게 정했는지"가 적혀 있다. 결론만 보고 바꾸면 이미 배제한 선택지로 되돌아간다. 이유를 읽고 따른다.
- `docs/99-decisions.md`의 "확인 과제"는 외부 확인(법 조문 등)이 필요한 사항이다. 추측하지 말고 사용자에게 묻는다.
- `docs/99-decisions.md`의 "만들지 않기로 한 것"은 의도적 제외다. 임의로 추가하지 않는다.
- 문서에 없는 판단이 필요하면 `docs/15-personas.md`의 세 사람(한서윤 관객, 박정훈 소유자, 이도현 운영자)에게 어떻게 닿는지 보고, **정하기 전에 사용자에게 묻는다.**
- 문서의 숫자(시간·수량·비율·보관 기간)는 `docs/99-decisions.md` "확정된 숫자"가 기준이다. 코드에 상수로 흩뿌리지 말고 한곳에 모은다.
