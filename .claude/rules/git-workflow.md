# 브랜치, 커밋, 이슈, PR 규칙

- 커밋: "<종류>: <한글 요약>" + 빈 줄 + 한글 본문(무엇을, 왜) + "Refs #이슈번호"
  예: feat: 좌석 선점 도메인 규칙 추가
- 이슈 제목: "[<종류>] <한글 요약>"
  예: [feat] 좌석 선점 기능 구현
- PR 제목: 이슈 제목과 같게
- squash 커밋: "<PR 제목> (#PR번호)"
  예: [feat] 좌석 선점 기능 구현 (#23)
- 브랜치: "<종류>/<이슈번호>-<영문-kebab-요약>"
  예: feat/22-seat-hold
- 종류: feat, fix, refactor, test, docs, chore, ci, build
- 커밋은 기능 단위로 쪼갠다. 한 PR에 보통 2~6개. 예: 도메인 규칙과 단위 테스트 -> 나가는 포트, 저장 어댑터, 마이그레이션 -> 유스케이스 -> API(컨트롤러, Request/Response) -> 통합 테스트. 각 커밋은 그 시점에 빌드가 통과해야 한다.
- 이슈와 PR에는 항상 담당자 @me, 종류 라벨, 영역 라벨, 해당 도메인 라벨, 마일스톤을 붙인다.
- PR 본문 첫 줄에 "Closes #이슈번호"를 둔다.
- 머지: gh pr merge <번호> --squash --subject "<PR 제목> (#<번호>)" --delete-branch. --body 에는 PR 본문의 "무엇을 만들었나" 요약을 넣는다.
