# domain 모듈 규칙

- **순수 자바만.** Spring, jOOQ, `jakarta.persistence`, 그 밖의 프레임워크를 import하지 않는다. 빌드 파일에도 추가하지 않는다.
- application 패키지를 import하지 않는다 (도메인은 유스케이스를 모른다).
- **규칙은 도메인 객체가 가진다.** 공제율 계산(`docs/08`), 조기예매 몫(`docs/05` `docs/14`), 티켓 상태 판단(`docs/14`), 검표 판정(`docs/10` `docs/14`) 같은 계산을 서비스에 두지 않는다.
- 상태를 바꾸는 건 의도가 드러나는 메서드로 한다(`ticket.cancel(reason, now)`). 아무 값이나 바꾸는 setter를 열지 않는다.
- 금액·기간·번호 같은 값은 값 객체(record)로 만든다.
- 현재 시각은 인자로 받는다. 도메인 안에서 시계를 직접 읽지 않는다 (테스트에서 시각을 고정할 수 있게).
- **저장하지 않고 계산하는 것**을 지킨다: 티켓의 "만료"·"입장 완료", 행사의 "매진"은 상태로 저장하지 않는다 (`docs/14` "저장하는 것과 계산하는 것").
- 도메인 테스트는 DB·Spring 없이 순수 단위 테스트로 쓴다. 문서의 예시 숫자(예: 80,000원, 공연 5일 전 → 공제 20%)를 테스트 케이스로 옮긴다.
