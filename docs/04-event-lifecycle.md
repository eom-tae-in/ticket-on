# 04. 행사 생애주기

## 행사 상태

| 상태 | 뜻 |
|---|---|
| **작성 중** | 위저드 진행 중, 임시저장 상태 |
| **판매 대기** | 완성됐지만 오픈 시각 전 |
| **판매 중** | 예매 가능 |
| **판매 중단** | 주최자가 멈췄거나 관리자 조치 (정지 2단계 · 페이지 내리기) |
| **판매 종료** | 예매 종료 시각 지남. 행사는 아직 안 함 |
| **행사 종료** | 마지막 회차가 끝남 |
| **정산 완료** | |
| **취소됨** | 공연한 회차 없이 전부 취소, 전원 환불 |

### "매진"은 상태가 아닙니다

매진을 상태로 만들면 **취소표가 나올 때마다 상태를 되돌려야** 합니다.

> 매진은 **잔여가 0인 순간의 표시**입니다. 상태는 "판매 중" 그대로입니다.

그래서 "전 회차 매진 → 판매 종료"도 틀립니다. **판매 종료는 시간으로만 결정됩니다.**

### 행사 상태와 회차 상태는 다릅니다

8회차 공연에서 3회차는 끝났고 5회차는 남았다면, 행사는 여전히 **판매 중**입니다.

| 회차 상태 | |
|---|---|
| 판매 중 | |
| 판매 종료 | 그 회차의 예매 종료 시각 지남 |
| 종료 | 그 회차가 끝남 |

### 시간이 운영 판단을 이깁니다

상태 8종 중 시간이 결정하는 것과 사람이 누르는 것이 섞여 있습니다. 겹칠 때는 **시간이 우선**입니다.

> 판매 중단 중에 마지막 회차의 예매 종료 시각이 지나면 → **판매 종료**

중단은 "판매 중"의 변형이고, 시간이 지나면 어차피 팔리지 않으므로 중단이라는 말의 의미가 없어집니다. 상태 축을 둘로 나눌 필요가 없습니다.

**"중단했던 이력"은 따로 남깁니다.** 상태는 덮어써도 기록은 남아야 관리자가 판단할 수 있습니다. 판매 종료 이후에는 재개가 무의미하므로 재개 버튼이 사라집니다.

**매진도 같은 원칙입니다** — 상태가 아니라 계산되는 표시입니다. 티켓의 "만료"도 그렇습니다 (`07` 참조).

### 전환 트리거

| 전환 | 누가 |
|---|---|
| 작성 중 → 판매 대기 | 운영진이 "판매 시작" + 검증 통과 |
| 판매 대기 → 판매 중 | **자동** (오픈 시각 도달) |
| 판매 중 → 판매 종료 | **자동** (마지막 회차의 예매 종료 시각) |
| 판매 종료 → 행사 종료 | **자동** (마지막 회차 종료 시각) |
| 행사 종료 → 정산 완료 | 관리자 수동 |
| 남은 회차 전부 취소 → 취소됨 또는 행사 종료 | 소유자, 또는 관리자 정지 3단계 (아래 "행사 취소") |
| 취소됨 → 정산 완료 | 관리자 수동. 환불·배상으로 마이너스면 미수금 (`11` 참조) |

**"마지막 회차"는 취소되지 않은 회차 중 마지막**입니다. 취소된 회차를 기다리느라 판매나 행사가 끝나지 않는 일이 없게 합니다 (아래 "회차 취소" 참조).

**회차 종료 시각이 없으면 행사 종료를 판정할 수 없습니다.** 그래서 회차 시간이 잠기는 시점(아래)에 입력을 요구합니다 (`02` 참조).

**취소된 행사도 정산을 거칩니다.** 전원 환불과 배상이 나가 정산액이 마이너스가 되는 경우가 바로 여기입니다. 정산 완료가 "이 행사는 끝났다"의 기준이라, 이 길이 없으면 취소된 행사가 영영 "정산 안 끝남"으로 남아 주최자를 닫을 수 없습니다 (`01` 참조).

### 상태별로 할 수 있는 것

| 상태 | 편집 |
|---|---|
| 작성 중 | 전부 |
| 판매 대기 | 전부 (예매가 아직 없음). 단 **초대권을 먼저 발권했으면 초대권이 걸린 것에 `09`의 잠금 항목**이 적용됨 |
| 판매 중 | 아래 수정 범위 적용 |
| 판매 종료 ~ 행사 종료 | **입구 목록 · 검표 계정만** |
| 행사 종료 이후 | **없음. 전부 고정** |

삭제는 상태가 아니라 **팔린 표나 초대권이 있었는지**로 정합니다 (아래 "행사 삭제").

### 판매 종료는 공연이 끝난 때가 아닙니다

판매 종료는 **마지막 회차의 예매가 마감된 때**입니다. 기본값이 시작 1시간 전이라, 공연 하나짜리 행사는 이렇게 흘러갑니다.

```
18:00  예매 마감 → 「판매 종료」      검표 시작
19:00  공연 시작
21:00  공연 끝   → 「행사 종료」
```

판매 종료부터 행사 종료까지는 **공연 당일 현장이 돌아가는 시간**입니다.

| | 판매 종료 ~ 행사 종료 | 행사 종료 후 |
|---|---|---|
| 제목 · 소개 · 포스터 | 고정 | 고정 |
| 도면 · 가격 · 회차 · 취소 규정 | 고정 | 고정 |
| 공개 수준 | 고정 | 고정 |
| **입구 목록 · 검표 계정** | **수정 가능** | 고정 |

**제목·소개·포스터를 얼리는 이유** — 판매가 끝나면 새로 살 사람이 없으니 바꿀 이유가 없습니다. 이때 바꾸면 이미 산 사람에게 뒤늦게 말을 바꾸는 것밖에 안 됩니다.

**입구 목록과 검표 계정만 남기는 이유** — 판매가 끝난 시점에는 현장이 이미 돌아가고 있습니다. 공연 하나짜리 행사는 기본값으로 판매 종료와 검표 시작이 같은 시각이고, 여러 회차나 종일형 행사는 앞선 회차의 검표가 이미 진행 중입니다. 얼리면 검표 도중에 손을 댈 수 없습니다.

> 18:10 — 정문 줄이 길어 옆문을 더 열기로 했습니다. 입구 목록에 "옆문"을 추가해야 스태프가 고를 수 있습니다.
> 18:20 — 검표 계정 비밀번호가 단톡방에 올라갔습니다. 바꿔야 합니다.

**도면이 고정되는 게 중요합니다.** 티켓은 좌석을 가리키기만 하므로 (`07` 참조), 끝난 행사의 도면이 바뀌면 지난 예매 내역의 좌석 번호가 바뀝니다.

**수정이 아닌 조치는 이 표와 별개입니다.** 각자의 규칙을 따릅니다.

| 조치 | 언제까지 |
|---|---|
| 회차 취소 · 행사 취소 | 시작하지 않은 회차가 있는 동안 (아래) |
| 초대권 발권 · 회수 | **판매 대기부터** 그 회차가 끝날 때까지 (`09` 참조) |
| 출연자 변경 알림 (주최자가 보내는 기한) | 회차형은 그 회차 시작 전, 종일형은 그날 운영 종료 전까지. 관객의 취소·포기 권리는 회차형은 시작 전, 종일형은 **그날 입장 전**까지 (아래) |
| 공연 지연 처리 | 그 행사 정산 완료 전, 그리고 행사 종료 30일 이내 — 대상을 정하는 입장 기록이 30일 뒤 삭제됨 (`08` 참조) |
| 공연 중단 처리 | 그 행사 정산 완료 전까지 (`08` 참조) |
| 정산 · 현황 보기 | 언제든 |

### 행사 삭제

> **결제된 예매와 초대권이 한 번도 없었으면 상태와 상관없이 지울 수 있습니다.**

| | |
|---|---|
| 작성 중 | 운영진 누구나 |
| 판매를 시작한 뒤 | **소유자** |
| 오픈 알림 신청자 | "행사가 삭제되어 예매가 열리지 않습니다" 이메일 (`12` 참조) |
| 공유된 링크 | "삭제된 행사입니다" |

> 가격을 잘못 넣고 판매를 시작했는데 아직 0건입니다. 지우고 새로 만들고 싶습니다 (`15` 박정훈).

**한 장이라도 팔렸거나 초대권을 발권했으면 지울 수 없습니다.** 전부 취소됐어도 결제·환불 기록이 법정 보존 대상이고, 초대권 링크가 이미 나갔습니다 (`11` 참조). 그때는 행사 취소를 씁니다.

## 예매가 열린 뒤(판매 중) 수정 범위

**판매 대기(판매 시작을 눌렀지만 오픈 전)는 예매가 없어 전부 고칠 수 있습니다** (위 표). 아래는 오픈해서 예매가 들어오기 시작한 뒤의 범위입니다.

**판매 대기에 초대권을 발권했으면, 아래 규칙 중 초대권이 걸린 것을 지키는 항목만 오픈 전부터 적용됩니다** — 그 좌석의 이동·삭제와 판매 제외 해제, 그 회차·구역 삭제, 회차 시간 변경 시 알림, 관계자 확보 수 하한, 장소 변경 승인 (`09` 참조). 정원·가격·취소 규정을 포함한 나머지는 계속 자유입니다.

아래 표에서 **"티켓"은 예매 티켓과 초대권 티켓을 모두 뜻하고, 취소·회수되지 않은 것만 셉니다.** 초대권 좌석도 받은 사람이 있는 자리라 팔린 좌석과 똑같이 지킵니다. 취소·회수된 티켓만 남은 좌석·회차·구역은 고치거나 지울 수 있고, 지워도 기록으로 남아 그 티켓에는 원래 좌석·회차가 그대로 보입니다 (`07` 참조).

| | 예매가 열린 뒤 |
|---|---|
| **장소** | **관리자 승인 필수** + 전원 통지 + 공제 면제 (아래 "장소 변경") |
| **회차 일시** | 주최자 단독은 **그 회차 시작 1주일 전까지**. 티켓이 있으면 그 회차 예매자·초대권 받은 사람에게 알림 + 예매 표에 공제 면제. 이후는 연기 절차 |
| 제목 · 포스터 · 소개 | 자유 변경 (**이력 보관**, `03` 참조) |
| 입구 목록 · 검표 계정 | 자유 변경 |
| 공개 수준 | 변경 가능 |
| 예매 종료 시각 | 변경 가능 |
| 정원 (수량형) | **늘리기만.** 판매 수량 이하로 줄일 수 없음 |
| 좌석 배치도 (도면) | **티켓이 걸린 좌석은 옮기거나 지울 수 없음.** 빈 좌석·빈 블록 추가, 티켓 없는 좌석 수정은 가능. 예외는 장소 변경뿐 (아래) |
| 블록 이름 | **변경 가능.** 티켓이 걸린 좌석의 표기도 함께 바뀜. 이력은 남기지 않음 (`02` 참조) |
| 판매 제외 좌석 | **회차별로 자유 변경.** 이미 팔린 좌석은 제외 불가. 초대권이 걸린 좌석은 제외를 풀 수 없음. 수량형 관계자 확보 수는 발권한 초대권 수 아래로 줄일 수 없음 |
| 가격 | **변경 가능하되 신규 예매부터 적용** |
| 회차 추가 | **가능** |
| 회차 · 구역 삭제 | **티켓이 있으면 불가** |
| 취소·환불 규정 | **불가.** 예매 시점 규정이 따라다님 |

**장소만 승인제인 이유** — 홍대 소극장인 줄 알고 샀는데 강남으로 바뀌면 사실상 계약 내용이 바뀐 겁니다. 반면 포스터·소개는 오타 수정이나 캐스팅 추가 같은 정상 업데이트가 대부분이라, 승인을 걸면 주최자가 오타 하나 고치려고 며칠을 기다립니다.

**회차 시간 잠금은 회차마다 따로입니다.** 8회차 공연이 이미 시작했어도 아직 열흘 남은 마지막 주 회차는 주최자가 바꿀 수 있습니다 (`15` 박정훈). 잠금은 그 회차를 산 사람을 보호하려는 것이라, 다른 회차가 시작했다고 함께 잠글 이유가 없습니다.

**티켓(예매·초대권)이 있는 회차의 시간을 바꾸면 연기와 같은 대우**입니다. 그 회차 예매자에게 이메일과 문자가 가고, 그 표에 공제 면제가 붙습니다. 바뀐 시간에 못 오는 사람이 공제를 물면 안 됩니다. 초대권 받은 사람에게도 발권 때의 수단으로 알림이 갑니다 (`09` 참조).

**회차 추가는 허용**합니다. 매진되면 회차를 더 여는 게 자연스럽습니다. 추가된 회차에도 기존 예매 설정(예매 종료 기준, 매수 제한 범위, 재입장)이 그대로 적용됩니다.

**빈 블록 추가도 허용**합니다. 가변석을 더 놓는 경우가 있고, 기존 좌석에 영향이 없습니다.

### 예매자에게 알리기

**큰 변경이면 모달이 뜹니다.** 오타 수정 같은 작은 변경에는 안 뜹니다.

| 변경 | |
|---|---|
| 제목 변경 | 모달 |
| 포스터 교체 | 모달 |
| 소개 글 대폭 수정 | 모달 |
| 소개 글 몇 글자 수정 | 조용히 저장 |
| **팔린 좌석이 있는 블록의 이름 변경** | 모달 |

> **변경 사항을 예매자에게 알릴까요?**
>
> ~~주연: 김배우~~ → **주연: 이배우**
>
> 예매자 312명에게 이메일과 문자가 발송됩니다.
>
> [알리지 않음]  [알리기]

**기본 선택이 없습니다.** ESC와 바깥 클릭도 막아 둘 중 하나를 반드시 고르게 합니다. 기본값을 두면 반사적으로 누르게 되어 모달을 둔 의미가 사라집니다.

**변경 내용을 비교해 보여주는 게 중요합니다.** 그냥 "알릴까요?"만 물으면 뭘 바꿨는지 기억 못 하고 대충 누릅니다.

**판단은 주최자가 합니다.** 관리자는 남의 공연 소개 글이 중요한 변경인지 알 수 없습니다. **제목·소개·포스터는 통지 여부가 변경 이력에 기록**되어, 나중에 "바꿨는데 안 알렸다"가 드러납니다. 블록 이름은 이력을 남기지 않으므로 통지 여부도 기록하지 않습니다 (`02` 참조).

**주요 출연자 교체는 이 모달로 끝나지 않습니다.** 알리는 것에 더해 관객에게 환불 권리가 생기므로 [출연자 변경 알림]을 따로 씁니다 (아래 "출연자 변경").

**취소 규정을 못 바꾸는 게 중요합니다.** 관대한 규정을 보고 예매했는데 나중에 빡빡해지면 안 됩니다.

## 판매 중단

주최자가 사정이 생겨 잠시 멈출 수 있습니다. 기존 예매는 유지되고 신규 판매만 멈춥니다. **재개도 가능**합니다.

**목록에서 숨기지 않습니다.** 어제 봤던 공연이 사라지면 관객이 더 혼란스럽습니다.

> ○○밴드 단독공연 · 3/14
> **판매 일시 중단**

**주최자가 한 줄 사유를 적을 수 있게** 하면 문의가 줄어듭니다.

**관리자가 멈춘 판매는 주최자가 재개할 수 없습니다** (정지 2단계, 페이지 내리기). [재개]에 "관리자 조치로 중단됨"이 표시되고, 해제된 뒤에야 주최자가 직접 재개합니다. 해제됐다고 저절로 열리지 않습니다 (`01` 참조).

**중단 중에도 취소는 가능합니다.** 판매를 멈춘 건 주최자 사정이고 환불 권리는 그대로입니다.

**중단 중에는 예매 변경이 불가능합니다.** 변경은 새 좌석을 선점하는 행위라 판매가 멈춘 상태와 모순됩니다.

> 현재 판매가 중단되어 변경할 수 없습니다. 취소는 가능합니다.

## 회차 연기

날짜가 바뀌는 경우입니다. **장소 변경과 같은 무게**로 처리합니다.

```
주최자가 회차 일시 변경 요청
  → 관리자 승인
  → 예매자 전원 통지
  → 같은 자리 그대로 이전
```

### 기존 회차의 날짜를 고칩니다

새 회차를 만들지 않습니다. **티켓이 그대로 붙어 있어 자동 이전이 공짜**입니다. 좌석도 그대로고 QR도 유효합니다.

새 회차를 만들면 티켓 수백 장을 옮기는 작업이 따로 필요하고, 그 과정에서 사고가 날 여지가 생깁니다.

**1주일 전 잠금의 예외입니다.** 연기는 임박해서 결정되는 경우가 많고 관리자 승인을 거치므로 기한 제한이 없습니다.

| | 기한 |
|---|---|
| 회차 시간 수정 (주최자 단독) | 그 회차 시작 1주일 전까지 |
| **연기 (관리자 승인)** | **제한 없음** |

### 관객은 아무것도 안 해도 됩니다

> 3/20 R석 12열 7번 → **3/27 R석 12열 7번**

선택 기한도 자동 환불도 없습니다. **공제 면제가 그 역할을 대신합니다.**

자동 환불을 검토했으나 폐기했습니다. 이메일 열람률이 30% 안팎이라 **기한 내 응답하지 않은 다수가 환불되어** 주최자가 관객의 3분의 2를 잃고, 관객도 갈 생각이었는데 티켓이 사라집니다. 되돌릴 방법이 없다는 게 결정적이었습니다.

### 공제 면제

**연기가 승인된 시점에 이미 예매한 티켓**에 면제 표시가 붙습니다. 이 티켓은 **이후 언제 취소해도 공제 0%** 입니다.

**같은 공제 면제가 붙는 경우는 넷입니다.** 모두 주최자 쪽 사정으로 산 표의 내용이 바뀐 경우입니다.

| 경우 | 붙는 시점 | 취소 시 배상 |
|---|---|---|
| 연기 | 관리자 승인 | 없음 |
| 장소 변경 | 관리자 승인 | 없음 |
| 회차 시간 수정 | 주최자 수정 | 없음 |
| **출연자 변경** | 주최자 알림 | **10% 배상** (아래) |

| | |
|---|---|
| 붙는 대상 | 변경 시점에 이미 산, 바뀐 회차의 티켓 (장소 변경은 모든 회차). **출연자 변경에서 묶음권은 예외** — 면제 대신 그날 포기 (아래 "출연자 변경") |
| 범위 | **그 행사, 그 티켓에만** |
| 승계 | 변경으로 새 티켓이 생기면 따라감 (`08` 참조) |
| 소멸 | 행사가 끝나면 함께 |
| 다른 행사 | 영향 없음 |

**쿠폰처럼 떼어서 다른 행사에 쓸 수 없습니다.** 변경도 같은 행사 안에서만 일어나므로 면제가 행사 밖으로 나갈 경로가 없습니다.

**연기 공지 이후 새로 예매한 사람은 면제 대상이 아닙니다.** 바뀐 날짜를 알고 샀으니까요. 다른 경우도 같습니다.

**여러 번 연기해도 면제는 유지**되고, 두 번째 연기 때 새로 산 사람도 그때부터 면제 대상이 됩니다.

### 연기된 회차도 계속 팝니다

판매가 멈추지 않습니다. 멈추고 싶으면 판매 중단을 쓰면 됩니다.

## 장소 변경

**관리자 승인**을 거칩니다. 승인되면 예매자 전원에게 이메일과 문자가 가고, 그 표에 **공제 면제**가 붙습니다. 배상은 없습니다.

**장소는 행사에 하나입니다.** 일부 회차만 다른 곳으로 옮길 수 없습니다. 그래야 하면 그 회차를 취소하고 새 행사로 엽니다.

**장소와 일시가 동시에 바뀌면 한 번에 신청하고 한 번에 승인**합니다. 따로 처리하면 통지가 두 번 가고, 첫 통지를 받고 환불한 사람이 두 번째 변경은 모르게 됩니다.

### 좌석 배치가 그대로면 주소만 바뀝니다

수량형이거나, 새 장소에서 기존 좌석 번호를 그대로 쓸 수 있으면 도면은 손대지 않습니다.

### 배치가 다르면 — 첫 회차 전에만 도면을 바꿉니다

> 개막 10일 전 극장 설비가 고장 나 같은 동네 120석 극장으로 옮깁니다. 이미 140장이 팔렸고 좌석 배치가 다릅니다 (`15` 박정훈).

다 환불하고 다시 팔게 하면 주최자는 배상만 수십만 원을 물고 관객도 잃습니다. 관객은 원하던 날 자리를 놓칩니다. 그래서 **좌석이 있는 티켓을 새 도면에 재배정**합니다. 예매 티켓과 초대권 티켓 모두입니다.

```
주최자가 새 도면을 그림 (구역 이름 · 가격은 기존과 같게)
  → 시스템이 재배정 안을 만듦
  → 주최자가 확인 · 조정
  → 관리자 승인
  → 전원 알림 (새 장소 + 새 좌석) + 공제 면제
```

| 재배정 규칙 | |
|---|---|
| 구역 | **그대로.** R석은 R석으로 |
| 일행 | **같은 예매 건은 붙여서** |
| 순서 | **원래 앞자리였던 사람부터 새 앞자리에** |
| 자리가 모자라면 | 그 회차·구역 자리가 티켓 수(예매 + 초대권)보다 적으면 **신청할 수 없음.** 구역을 다시 나누거나 회차 취소를 씀 |
| 판매 제외 좌석 | 옛 도면의 설정은 옮기지 않음. 주최자가 새 도면에서 회차별로 다시 지정 |
| 기록 | 재배정표(옛 좌석 → 새 좌석)를 주최자 이력에 보관. "원래 12열 7번이었다"를 확인할 수 있게 |

**티켓이 가리키는 좌석이 바뀌는 유일한 예외**입니다 (`07` 참조). 관리자 승인과 전원 통지를 거치는 명시적 절차라 허용합니다. 관객은 가만히 있어도 자리가 있고, 마음에 안 들면 공제 없이 취소하거나 바꿉니다.

**첫 회차가 시작된 뒤에는 도면을 바꿀 수 없습니다.** 이미 공연한 회차 표의 좌석 번호가 바뀌기 때문입니다. 그때 배치가 다른 곳으로 옮겨야 하면 남은 회차를 취소하고 새 행사로 엽니다.

## 출연자 변경

> 3/15 회차 주연이 김배우에서 이배우로 바뀌었습니다. 공연은 그대로 합니다 (`15` 박정훈, 한서윤).

소비자분쟁해결기준은 **주요 출연자 교체를 "입장료 환급 + 10% 배상"** 사유로 봅니다 (`99` A-1). 소개 글을 고치는 것만으로는 부족합니다.

```
[출연자 변경 알림] (소유자)
  → 회차 선택 + 변경 내용 ("주연 김배우 → 이배우")
  → 즉시 적용
     · 그 회차를 이미 산 사람에게 이메일 + 문자
     · 그 표에 공제 면제 + 취소 시 10% 배상
     · 그 회차 출연 칸이 있으면 새 내용으로 바뀜 (`02`)
```

| 규칙 | |
|---|---|
| 누가 | **소유자** (배상이 걸림) |
| 대상 | 알림 **이전에** 산 표. 이후에 산 사람은 알고 산 것 |
| 공연 | 그대로. **자동 환불하지 않음** — 원하는 사람만 취소 |
| 관객이 권리를 쓸 수 있는 기한 | 회차형은 그 회차 시작 전, 종일형은 **그날 입장 전**까지 (주최자가 알림을 보낼 수 있는 기한은 위 "수정이 아닌 조치" 표) |
| "주요 출연자"인지 | 주최자가 먼저 판단. 다툼은 관리자 |
| 주최자가 안 알리면 | 관객 신고 → 관리자가 변경 이력(`03`)으로 확인 후 **대신 같은 처리** |

**자동 환불하지 않는 이유** — 공연은 열립니다. 바뀐 배우라도 보러 오겠다는 사람의 표를 없앨 이유가 없고, 주최자도 회차가 통째로 비지 않습니다.

### 묶음권은 바뀐 날만 포기합니다

> 페스티벌 둘째 날 헤드라이너가 바뀌었습니다. 3일권을 산 관객이 있습니다 (`15` 이도현).

| 관객의 선택 | 결과 |
|---|---|
| **그날만 포기** | 그날 몫 환불 + 10% 배상 (`08` 참조). 나머지 날은 그대로 입장 |
| 그냥 감 | 아무 일 없음 |

- **첫날 입장했어도 포기할 수 있습니다.** 바뀐 건 그날이고, 주최자 쪽 사정입니다. 주최자가 하루를 취소한 경우와 같은 원리입니다 (`08` 참조)
- **기한은 그날 입장 전**입니다. 당일 아침에 빠져도 들어가기 전이면 포기할 수 있습니다
- 포기한 날에 QR을 찍으면 **"환불받은 날짜입니다"** 로 막힙니다 (`10` 참조)

**묶음권에는 공제 면제가 붙지 않습니다.** 붙으면 하루 바뀐 것으로 3일권 전체를 공제 없이 취소할 수 있게 됩니다. 묶음권이 받는 권리는 **그날 포기 하나**입니다.

> 처음에는 "묶음권은 전체 취소에 면제·배상"이었으나, 하루 바뀌었는데 3일 전체를 돌려주고, 첫날 입장 뒤에는 아무것도 못 받는 문제가 있어 바꿨습니다.

| | 연기 | 회차 취소 |

| 승인 | 관리자 | 소유자 혼자 |
| 배상 | 없음 | 주최자 부담. 불가항력이면 없음 (아래) |

그래서 취소 버튼을 누르면 **먼저 이 상황을 숫자로 보여줍니다.**

```
⚠️ 3/15 19:00 회차를 취소하려고 합니다

이 회차 예매자                48명
다른 회차에 남은 자리 합계     30석

→ 다른 회차로는 전원이 옮길 수 없습니다.
  날짜를 새로 잡을 수 있다면 [연기 신청]을 쓰세요.
  예매자의 자리가 그대로 옮겨집니다.

[연기 신청으로 가기]   [그래도 취소하기]
```

**판단은 주최자가 합니다.** 취소를 고르면 배상 부담과 관객 불만도 주최자 몫입니다.

| 규칙 | |
|---|---|
| 누가 | **소유자.** 관객에게 불리하지 않으므로 (전액 환불 + 배상) 관리자 승인 불필요 |
| 언제까지 | 그 회차 시작 전까지. 이미 시작한 공연은 취소가 아니라 중단·지연 처리 (`08` 참조) |
| 남은 자리 | 다른 회차는 평소처럼 선착순 |

**주최자 혼자 눌러도 되는 이유** — 연기는 관객이 원하지 않는 날짜로 표가 옮겨질 수 있어 관리자 승인을 받습니다. 취소는 돈을 다 돌려받으니 관객 손해가 없습니다. 그리고 **배상을 주최자가 부담**하므로 가볍게 누를 수 있는 버튼이 아닙니다.

### 불가항력이면 배상이 없습니다

소비자분쟁해결기준은 주최자 사정으로 취소하면 **"환급 + 10% 배상"**, 천재지변 같은 불가항력이면 **"환급"** 만 정합니다 (`99` A-1).

| 사유 | 환불 | 배상 |
|---|---|---|
| **주최자 사정** — 배우 부상, 극장 고장, 대관처 사정 등 | 즉시 전액 | 10%, 즉시 |
| **불가항력** — 태풍·지진 같은 천재지변, 정부의 공연 금지 조치 | 즉시 전액 | **관리자 확인까지 보류.** 인정되면 없음, 아니면 지급 |

> 페스티벌 둘째 날이 태풍으로 취소됐습니다. 하루 800명에게 10%씩이면 280만원입니다 (`15` 이도현).

**환불은 어느 쪽이든 기다리지 않습니다.** 관객이 받는 돈의 대부분은 환불이고, 배상만 확인을 기다립니다.

**보류한 배상의 뒤처리**

| | |
|---|---|
| 취소 알림 | "배상 여부는 확인 후 알려드립니다" 문구를 넣음 |
| 관리자 결정 후 | **지급이든 면제든 결과를 관객에게 이메일로** 알림. 주최자에게도 알림 |
| 정산 | 확인이 끝나지 않은 배상이 있으면 그 행사는 **정산 완료를 누를 수 없음.** 돈 계산이 확정되지 않았으므로 |
| 처리 목록 | 정산 기한(영업일 7일)이 다가오는 건은 강조 (`12` 참조) |

**관리자가 확인하는 이유** — 주최자가 고르게만 하면 모든 취소가 불가항력이 됩니다.

> 처음에는 이유와 상관없이 10% 배상이었으나, 법 기준보다 주최자에게 가혹해 바꿨습니다.

같은 구분이 **행사 취소, 공연 중단**에도 적용됩니다 (`08` 참조).

### 남은 회차가 없어지면

마지막으로 남은 회차를 취소하는 경우 경우를 둘로 나눠 알립니다.

| | 경고 | 행사 상태 |
|---|---|---|
| **아직 열린 회차가 없음** | "이 회차를 취소하면 남은 회차가 없어 **행사 전체가 취소됩니다**" | **취소됨** |
| **이미 열린 회차가 있음** | "남은 회차가 없어 **행사가 종료됩니다.** 진행된 회차는 정상 정산됩니다" | **행사 종료** → 정산 |

8회차 중 7회차를 이미 공연했다면 행사가 "취소됨"이 되면 안 됩니다. 7회차분은 정상적으로 정산해야 합니다.

## 행사 취소

> **행사 취소 = 아직 시작하지 않은 회차를 전부 취소하는 것**

회차 취소를 한 번에 하는 버튼입니다. 규칙도 회차 취소와 같습니다.

| | |
|---|---|
| 누가 | **소유자만** (관리자는 정지 3단계로, `01` 참조) |
| 언제까지 | **시작하지 않은 회차가 하나라도 있는 동안** |
| 환불 | 남은 회차 예매자 전원 전액 환불 + 10% 배상 (불가항력이면 배상 보류, 위 참조) |
| 이미 공연한 회차 | **환불하지 않고 정상 정산** |
| 결과 상태 | 공연한 회차가 없으면 **취소됨**, 있으면 **행사 종료** → 정산 |

> 8회차 중 5회차를 공연한 뒤 극장에 물이 새서 남은 3회차를 못 합니다 (`15` 박정훈).
> → 3회차 예매자만 환불, 5회차분은 정산됩니다.

> ⚠️ 남은 3회차의 예매자 186명이 전원 환불됩니다. 되돌릴 수 없습니다.
> 사유: ○ 주최자 사정 ○ 불가항력
> 확인을 위해 행사명을 입력하세요: `________`

**정지 3단계만 예외**입니다. 사기로 공연이 실제로 열리지 않았다면 관리자가 지난 회차까지 환불할 수 있습니다 (`01` 참조).

**취소 이력은 주최자에 남습니다.** 행사 취소와 회차 취소 모두입니다. 관리자가 주최자 상세에서 볼 수 있고, 승인 심사와 정지 판단의 근거가 됩니다. **관객에게는 공개하지 않습니다** — 주최자 페이지에 "과거 취소 2건"을 띄우면 과한 낙인입니다. 같은 이유로 **전부 취소된 행사는 주최자 페이지의 지난 행사 목록에서 뺍니다** (`01` 참조).

"주최자 자발적 취소"와 "관리자 강제 취소(정지 3단계)"는 구분해 기록합니다.

## 끝난 행사의 공개 페이지

**목록에서는 빠지지만 페이지는 남습니다.**

| | 행사가 끝난 뒤 |
|---|---|
| 목록 · 검색 | **빠짐** — 예매할 수 없으니 |
| **행사 페이지** | **남음** — "종료된 행사" 배지 + 예매 버튼 없음 |
| 포스터 · 소개 · 장소 | 그대로 |
| 좌석 배치도 | 안 보임 (고를 게 없음) |
| 관객의 예매 내역 | "지난 예매"로 내려감 (`13` 참조) |

**남겨야 하는 이유가 셋입니다.**

- **공유된 링크가 깨지지 않습니다.** SNS와 단톡방에 뿌린 링크가 "없는 페이지"가 되면 안 됩니다
- **주최자의 과거 이력**입니다. 주최자 페이지의 "지난 행사"로 모여, 다음 행사를 홍보할 때 지난 공연을 보여줄 수 있습니다 (`01` 참조)
- 관객이 "작년에 뭘 봤나"를 확인합니다

**주최자는 끝난 행사 페이지를 내릴 수 없습니다.** 공개 수준도 판매 종료 후 고정이고, 끝난 행사는 이미 목록에서 빠져 있으므로 링크 전용으로 바꿔도 달라지는 게 없습니다. 내용에 문제가 있으면 **관리자가 페이지를 내립니다** (`01` 참조).

### 행사가 끝난 뒤 일어나는 일

```
행사 종료
 ├─ 즉시             목록에서 빠짐 · QR 버튼 사라짐 · 공유 링크 만료 · 편집 전부 고정
 ├─ 영업일 7일 이내   정산 → 관리자가 "정산 완료" 처리 (`11` 참조)
 ├─ 30일             입장 기록 삭제, 집계 숫자만 남음 (`10` 참조)
 ├─ 6개월            제목·소개·포스터 변경 이력 삭제 (`03` 참조)
 └─ 5년              관객 개인을 알아볼 수 있는 정보 삭제, 집계만 남음 (`11` 참조)
```

| 누가 | 볼 수 있는 것 |
|---|---|
| 산 사람 | 예매 카드 (좌석·금액·취소 내역), 결제·환불 내역 |
| 아무나 | 옛 링크로 종료된 행사 페이지, 주최자 페이지의 지난 행사 목록 |
| 주최자 | "지난 행사" 묶음에서 예매 현황·입장 현황·정산. **복제는 가능, 편집은 불가.** 삭제는 팔린 표·초대권이 없었던 행사만 (위 "행사 삭제") |
| 관리자 | 전부 |

**행사가 취소된 경우도 같습니다.** 배지만 "취소된 행사"로 다릅니다. 다만 **전부 취소된 행사는 주최자 페이지의 지난 행사 목록에서 빠집니다** (`01` 참조). 링크로 들어오면 페이지는 보입니다.

`11`의 원칙이 그대로 적용됩니다 — **화면에서 내리는 것과 지우는 것은 다릅니다.**

## 작성 중 행사 관리

**개수 제한은 없습니다.** 여러 행사를 동시에 준비하는 건 정상입니다.

막는 장치가 없으니 **유도 장치가 일해야 합니다.**

```
작성 중 (2)
┌──────────────────────────────┐
│ ○○밴드 단독공연               │
│ 4/7 단계 · 가격 설정까지 완료   │
│ 마지막 수정 3일 전             │
│                [이어서 작성]   │
└──────────────────────────────┘
```

진행률, 마지막 수정일, 멈춘 단계로 바로 가는 버튼. 목록 상단에 별도 구역으로 둡니다.

| 시점 | 처리 |
|---|---|
| 30일 미수정 | 알림 |
| 회차 날짜가 이미 지남 | **목록에서 접어둠** + 정리 안내 |
| 그 이후 | 그대로 보관 |

**자동 삭제는 하지 않습니다.** 작업물을 시스템이 지워버리면 주최자가 크게 화를 냅니다.

## 행사 복제

정기공연 주최자는 매번 처음부터 만듭니다. 복제가 있으면 작성 중 행사가 애초에 덜 생깁니다.

- 종료된 행사든 진행 중인 행사든 복제 가능
- 복제본은 **"작성 중" 상태**로 시작, 이름은 `○○공연 (복사본)`
- **도면은 통째로 복사됩니다.** 복제한 뒤로 원본과 복사본은 아무 관계가 없습니다. 올해 도면을 고쳐도 작년 행사는 그대로입니다 (`02` 참조)

| 가져오는 것 | 가져오지 않는 것 |
|---|---|
| 도면 — 좌석 배치도 · 블록 · 구역 | 날짜 · 회차 |
| 가격 | 예매 기록 |
| 입구 목록 | 초대권 |
| 예매 설정 (매수 제한, 재입장 등) | 검표 계정 |
| 소개 글 | **조기예매** (기간이 과거) |
| | **쿠폰** (코드·사용 횟수가 이전 것) |
| | **공개 수준** (기본값 공개로 시작) |

**공개 수준을 물려받지 않는 이유** — 비공개를 물려받으면 주최자가 깜빡하고 그대로 열어서 **아무도 못 찾는 행사**가 됩니다. 공개로 시작하면 판매 전에 알아차립니다.

날짜만 바꾸면 바로 판매를 시작할 수 있어야 합니다.
