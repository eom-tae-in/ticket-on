# 06. 예매 흐름

## 전체 흐름

```
행사 목록 → 행사 상세 → [예매하기] → 로그인
  → 회차 선택 (또는 날짜 · 묶음권)
  → 좌석 선택 (지정형) 또는 매수 선택 (수량형)   ← 타이머 10분 시작
  → 쿠폰 입력
  → 예매자 정보 확인   ※ 계정 정보 자동, 확인만
  → 동의 (취소 규정 · 연령 · 좌석 속성)
  → 결제                                        ← 타이머 7분 재설정
  → 완료 · 티켓 발급
```

**행사 상세까지는 로그인이 필요 없습니다.** 주최자가 링크를 뿌리는 게 주된 홍보 수단인데, 로그인 벽이 있으면 홍보 자체가 막힙니다.

**로그인 후에는 보던 행사의 예매 화면으로 정확히 돌아와야 합니다.**

**연령 제한 행사는 회차를 고르는 순간 나이를 봅니다.** 생년월일상 그 회차 날짜에 나이가 모자라면 좌석 선택으로 넘어가지 않습니다 (`03` 참조). 좌석을 잡은 뒤에 막으면 타이머와 선점이 헛돕니다.

**이용 정지된 계정은 [예매하기]에서 막힙니다** (`01` 참조).

**회차를 먼저 고릅니다.** 좌석 재고는 회차마다 따로 관리되므로, 날짜를 정하지 않으면 어떤 자리가 남았는지 보여줄 수 없습니다.

**할인 선택 단계는 없습니다.** 증빙 할인을 전부 뺐으므로 조기예매는 자동 적용되고 쿠폰만 입력받습니다 (`05` 참조).

## 좌석 선점

### 언제부터 잠그나 — 좌석 클릭 즉시

고른 자리가 확실히 내 것이 됩니다. 다음 화면에서 "이미 팔렸습니다"가 뜰 일이 없습니다.

"다음 버튼을 눌렀을 때"나 "정보 팝업에서 확정할 때"도 검토했지만, 전자는 뺏길 위험이 크고 후자는 클릭 수가 배로 늘어납니다(4석이면 8번).

### 선점이 잠그는 것 셋

```
선점 (10분)
 ├─ 좌석 N개  또는  구역 + 수량
 ├─ 조기예매 몫 N개
 └─ 가격
```

**셋을 한 묶음으로 잠급니다.** 그래야 조기예매가 3만원인 걸 보고 고른 사람이 결제하는 사이 소진돼도 3만원으로 삽니다 (`05` 참조).

**선점은 예매 건보다 먼저 존재합니다.** 좌석 선택 화면에 들어가는 순간 생기고, 결제창을 열 때 예매 건이 만들어집니다.

### 타이머 두 개

| 단계 | 시간 | 시작 시점 |
|---|---|---|
| 좌석 선택 ~ 동의 | **10분** | **좌석(또는 매수) 선택 화면 진입** |
| 결제 | **7분** | **결제창을 여는 순간** 다시 시작 |

**쿠폰 입력 · 정보 확인 · 동의는 10분 안에서** 합니다. 쿠폰 코드를 찾느라 1~2분 써도 충분합니다 (`15` 한서윤). 7분은 앱 전환, 카드 인증처럼 **결제창 안에서 생기는 지연**을 위한 것입니다. 쿠폰 단계에서 다시 걸면 좌석을 붙잡는 시간만 길어집니다.

**회차 선택 단계에서는 타이머가 돌지 않습니다.** 아직 아무것도 잠그지 않으니까요. 8회차 공연에서 날짜를 고민하다 3분을 써도 좌석 고를 시간은 10분 그대로입니다.

**수량형도 같습니다.** 매수 선택 화면 진입부터 10분이고, 재고를 잠그는 건 똑같습니다.

**묶음권도 타이머 하나**입니다. 좌석 선택이 없어 10분이면 충분합니다.

**동시에 선점할 수 있는 좌석 수 = 1회 선택 매수**입니다. 4석으로 정했으면 5번째는 아예 눌리지 않습니다. **묶음권은 티켓 장수로 셉니다** — 3일권 4장은 4매 (`05` 참조).

타이머가 화면 진입부터 돌고 매수 상한이 있으므로 **"마구잡이로 다 선점"은 구조적으로 불가능합니다.**

### 표시와 만료

타이머는 상단에 계속 보여야 하고, **2분 남으면 눈에 띄게** 바뀌어야 합니다. 갑자기 사라지는 게 제일 나쁩니다.

만료되면 "시간이 초과되어 좌석이 해제되었습니다" 안내와 함께 **좌석 선택 화면으로 돌려보냅니다.**

### 두 사람이 동시에 같은 자리를 눌렀다면

먼저 도달한 쪽이 가집니다. 진 쪽에게는 **"방금 다른 분이 선택했습니다"** 를 띄우고 그 좌석을 즉시 회색으로 바꿉니다. 조용히 실패하면 관객이 계속 다시 누릅니다.

### 선점 반복 악용

결제 없이 좌석만 잡았다 버리기를 반복하면 **비용이 0원**이라 재고를 묶을 수 있습니다.

**제한을 걸지 않습니다.** 1만 명 이하 규모에서 매크로가 붙을 유인이 낮고, 이미 막는 장치가 있습니다 — 한 번에 선점할 수 있는 좌석은 1회 선택 매수까지이고, 타이머는 화면에 들어오는 순간부터 돕니다.

> 처음에는 "제한은 나중에 걸고 지금은 만료 횟수만 기록"하는 안이었으나, 단계를 나누지 않기로 하면서 쓸 곳이 없는 기록이 되어 뺐습니다.

> **예매·취소 반복은 신경 쓰지 않아도 됩니다.** 실제 결제가 일어나 돈이 묶이고, 취소하면 좌석이 즉시 풀려 남이 가져가므로 얻는 게 없습니다. 쌓이는 데이터 양도 정상 운영분에 비하면 미미합니다.

## 결제

### 결제창을 열기 전에 예매 건을 먼저 만듭니다

무엇을, 어느 자리로, 얼마에 사려는지가 기록된 뒤에 결제가 진행됩니다.

- **승인은 났는데 우리 쪽에 기록이 없는 상황**을 막습니다
- **실패한 건도 남아** 재시도가 쉽습니다
- **가격이 고정됩니다**

### 가격은 선점 시점 기준

관객이 조기예매가 3만원을 보고 좌석을 잡았는데 결제하는 사이 소진됐다면 **3만원으로 고정**됩니다. 그래서 **좌석과 할인 자격을 한 묶음으로 잠급니다** (`05` 참조).

### 타이머는 결제창을 열면 재설정

> **돈을 받았으면 좌석은 반드시 준다.**

결제가 진행 중인 건은 자리를 유지합니다. 그럼에도 승인은 났는데 좌석 확정이 안 되는 경우가 남으면 **자동 환불 + 사과 안내**가 최후 방어선입니다.

### 실패·중단·이탈을 구분합니다

| 상황 | 좌석 처리 |
|---|---|
| **결제 실패** (한도 초과, 인증 실패) | **유지.** 남은 시간 복원, 재시도 가능 |
| **관객이 결제창을 닫음** | **유지.** 이전 화면으로 복귀 |
| **브라우저를 닫고 사라짐** | 타이머 만료로 자동 해제 |

**결제 실패 시 좌석을 바로 풀면 안 됩니다.** 다른 카드로 다시 시도하려는데 자리가 사라지면 그대로 이탈합니다. 실패는 "포기"가 아닙니다.

### 응답이 안 오는 결제

승인을 요청했는데 답이 없으면 승인 여부를 알 수 없습니다. **나중에 다시 확인하는 절차가 필요합니다.** 응답 없는 건을 표시해두고 일정 시간 뒤 결제 상태를 조회해 맞춥니다.

### 예매 건의 결제 상태

**결제가 어디까지 왔는지만** 나타냅니다. 취소 여부는 예매 건이 아니라 티켓마다 기록합니다 (`07` 참조).

| 결제 상태 | 뜻 |
|---|---|
| 결제 대기 | 예매 건 생성됨, 결제 진행 중 |
| 결제 완료 | 확정, 티켓 발급 |
| 결제 실패 | 재시도 가능, 좌석 유지 |
| 확인 필요 | 응답 없음, 대조 대기 |

**"만료"는 예매 건의 상태가 아닙니다.** 결제창을 열기 전에 타이머가 끝나면 예매 건은 아직 없습니다. **만료는 선점의 일**입니다 (`14` 참조).

**결제 대기 건은 주최자 판매 현황에 표시하지 않습니다.**

**예매 건에 "부분 취소됨" 같은 상태는 두지 않습니다.** 무엇이 취소됐는지는 티켓 하나하나가 취소 시각과 사유로 말해줍니다 (`07` 참조).

## 매수 제한

### 두 가지를 구분합니다

- **1회 선택 매수** — 한 번 예매할 때 담을 수 있는 좌석 수
- **1인 총 매수** — 한 사람이 정해진 범위에서 총 몇 장까지

### 1회 선택 매수 — 주최자 입력 + 비율 피드백

**자동 규칙으로 만들지 않습니다.** 제한의 필요성은 좌석 수가 아니라 수요 대비 공급에서 나오는데, 우리는 그 공연이 얼마나 팔릴지 모르고 주최자는 압니다.

> 1회 선택 매수 **[4]** 석
> 전체 200석의 2%입니다.

숫자를 바꾸면 비율이 갱신됩니다. **위험선(8석 초과 또는 전체의 10% 초과)을 넘으면 경고만** 합니다.

> ⚠️ 8석은 전체 50석의 16%입니다. 한 사람이 객석의 상당 부분을 가져갈 수 있습니다.

막지는 않습니다. 단체 관람을 받는 행사도 있으니까요. **기본값 4석을 미리 채워둡니다.**

### 1인 총 매수 — 기준을 고릅니다

| 기준 | 8회차(4일×2회) 공연에서 4매 제한이면 |
|---|---|
| **날짜별** | 최대 16매 |
| **행사 전체** | 4매 |

시간 회차별 기준은 두지 않습니다. 같은 날 15시와 19시를 다 사면 우회되기 때문입니다.

**단일 회차 행사에서는 이 선택 자체를 보여주지 않습니다.** 날짜가 하나뿐이라 둘이 같은 값입니다.

### 회차 선택 제약

**기본값은 "제한 없음"** 입니다.

> ○ 제한 없음
> ○ 하루에 한 회차만
> ○ 행사 전체에서 한 회차만

관객이 어기면 그 자리에서 알려줍니다.

### 집계 기준

**계정 기준이고, 계정은 전화번호 하나에 하나**입니다 (`01` 참조). 관객이 본인 번호를 적는다는 전제 아래 **사실상 사람 단위**입니다.

일부러 다른 번호를 적어 계정을 더 만들면 뚫립니다. 전제 밖의 일로 감수합니다. 번호를 바꿔가며 반복하는 사람은 관리자가 이용 정지합니다 (`01` 참조).

**초대권은 매수 제한에 포함되지 않습니다.** 주최자가 의도해서 준 것이라 제한할 이유가 없습니다.

## 예매 오픈

### 선착순만 (추첨은 만들지 않음)

추첨은 응모 → 마감 → 추첨 → 당첨 통지 → 결제 기한 → 미결제 처리 → 예비 당첨까지 **예매 흐름을 한 벌 더 만드는 일**입니다.

게다가 지정석과 궁합이 나쁩니다. 자동 배정은 관객 불만이 크고, 당첨자끼리 순서대로 고르게 하면 결국 또 선착순이 벌어집니다.

### 오픈 시각

**행사 단위로** 지정합니다. 회차마다 다르게 열면 관객이 헷갈립니다.

**관객 화면에는 서버 기준 남은 시간을 카운트다운**으로 띄웁니다. 기기마다 시계가 다르니 "오후 2시 오픈"만 적으면 누구는 일찍 누르고 누구는 늦습니다.

### 오픈 전에도 행사 페이지는 공개

> **예매 시작까지 2일 14:23:07**
> [🔔 알림 받기]

**알림 받기**는 로그인한 사용자만 가능하고 **언제든 해제**할 수 있습니다. 오픈 알림이 나간 뒤에는 목록에서 자동으로 빠집니다.

주최자에게는 **오픈 전 관심도 지표**이기도 합니다. 알림 신청이 정원의 세 배면 매진을 예상할 수 있습니다.

### 대기열은 두지 않습니다

1만 명 이하이므로 먼저 요청이 도달한 순서로 처리합니다.

## 예매 종료

| | 기준 |
|---|---|
| 회차형 | 회차 시작 **1시간 전** |
| 종일형 | 마지막 입장 **1시간 전** |

**주최자가 조정할 수 있되 기본값은 1시간 전**입니다.

"회차 시작 시각"을 기본값으로 두면 공연 시작 5분 전에 예매가 들어옵니다. 관객은 도착도 못 하고 현장은 당황합니다.

**전날 마감은 기본값으로 두지 않습니다.** 전통적으로 전날 마감하는 이유는 검표 명단을 종이로 뽑기 위해서인데, 우리는 QR 검표에 실시간 수동 검색까지 있어 명단을 미리 뽑을 필요가 없습니다. 전시는 당일 방문이 주류고, 소극장 공연도 매진이 안 된 경우 당일 관객이 귀합니다.

## 현장 판매는 서비스 밖

주최자가 현장에서 따로 팔면 재고가 어긋납니다. **현장 판매분은 관계자석으로 빼두는 게 맞습니다** (`09` 참조).
