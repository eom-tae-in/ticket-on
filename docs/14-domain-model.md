# 14. 도메인 모델

**무엇이 무엇을 가리키는가**를 한 장에 모은 문서입니다. 각 기능의 규칙은 해당 문서에 있고, 여기는 관계만 봅니다.

이 문서를 그리는 과정에서 `02`·`05`·`07`의 모순 세 개가 드러나 고쳤습니다. 맨 아래에 무엇이 바뀌었는지 정리해 두었습니다.

## 전체 관계도

```
주최자 (단체)                    ← 상태: 심사 중 / 활동 / 닫힘 / 영구 정지. 닫혀도 지우지 않음. 공개 정보: 소개 · SNS · 로고(선택)
 ├─ 소유자 1명 · 운영자 N명      ← 사람은 각자 로그인으로 소속. 한 사람이 여러 주최자에 소속 가능
 │   └─ 소속 이력 (역할 · 기간)  ← 나가도 남음. 운영진 프로필의 "참여한 주최자"
 │       사람: 닉네임 · 한 줄 소개 (운영진만. 관객 계정과 연결하지 않음)
 └─ 행사
     │
     ├─ 【도면】  회차와 무관. 행사에 하나
     │   ├─ 블록 ─ 좌석            ← 번호를 매김
     │   ├─ 구역                   ← 가격을 매김
     │   │   └─ 좌석을 구역에 배정
     │   └─ 입구
     │
     ├─ 【재고】
     │   └─ 날짜
     │       └─ 회차                ← 재고가 붙는 유일한 곳
     │           ├─ 가격 조정        (회차당 하나, 모든 구역에 같이 적용. `05`)
     │           ├─ 출연 (선택)      (변경 이력 대상. `02`)
     │           ├─ 좌석별 판매 상태  (지정형)
     │           ├─ 정원 · 잔여      (수량형)
     │           ├─ 관계자 확보 수   (수량형. 초대권에 씀, `09`)
     │           ├─ 판매 제외 좌석
     │           └─ 티켓 없는 입장 기록  (인원 · 사유 · 처리한 운영진)
     │
     ├─ 【상품·할인】
     │   ├─ 묶음권 상품 ─ 날짜 N개를 묶음
     │   ├─ 조기예매     (구역별 · 상품별 적용)
     │   └─ 쿠폰
     │
     ├─ 검표 계정
     ├─ 변경 이력 (제목 · 소개 · 포스터 · 회차 출연)
     └─ 장소 변경 재배정표 (옛 좌석 → 새 좌석)

관객 계정
 ├─ 알림함 (보낸 알림 기록 · 처음 본 시각)
 ├─ 선점                            ← 결제 전 10분
 │   └─ 좌석 또는 수량 + 조기예매 몫 + 가격
 │
 └─ 예매 건 ─────────────┐
     └─ 결제·환불 내역    │
                          ├─ 티켓
주최자                    │   ├─ 회차 1개 이상    (묶음권은 N개)
 └─ 초대권 ───────────────┘   ├─ 구역
                              ├─ 좌석 0개 또는 1개
                              ├─ 결제액 · 적용 할인
                              ├─ 공제 면제 · 취소 시 배상 · 회차별 포기 표시
                              ├─ QR 열쇠 ─ 공유 링크
                              └─ 입장 기록 N개
                                   └─ 회차 · 시각 · 입구 · 검표 수단 · 강제 통과
```

# 세 개의 층

## 1층 — 도면

> **극장이 어떻게 생겼는가.** 회차와 무관합니다.

| | 역할 |
|---|---|
| **블록** | 좌석 **번호**를 유일하게 만드는 덩어리 (1층, 2층) |
| **좌석** | 블록 안의 개별 자리. 속성(휠체어·시야제한)을 가짐 |
| **구역** | **가격**을 매기는 묶음 (R석, 스탠딩A). 지정형 / 수량형 |

**구역과 블록은 다른 축입니다.** 한 구역이 여러 블록에 걸칠 수 있고 그 반대도 됩니다 (`02` 참조).

**도면은 행사에 하나뿐입니다.** 회차마다 다를 수 없습니다.

> 8회차 공연에 도면이 8개 생기면, 구역 기본가도 8벌이 됩니다. `05`의 "기본가는 하나, 회차에는 조정값만"이 성립하지 않습니다.
>
> 같은 극장에서 같은 작품을 올리므로 실제로 달라지는 경우가 거의 없습니다. 연극제처럼 회차마다 작품이 바뀌어도 **극장 좌석은 그대로**입니다. 정말 다르면 **행사를 따로 만듭니다** — 관객에게도 다른 행사로 보이는 게 자연스럽습니다.

**"이 회차만 앞 두 줄을 안 판다"는 도면이 아니라 재고 쪽에서 해결됩니다.** 아래 참조.

### 도면은 행사마다 따로 갖습니다

**다른 행사와 도면을 같이 쓰지 않습니다.** 복제하면 통째로 복사되고, 그 뒤로 원본과 아무 관계가 없습니다 (`02` · `04` 참조).

여러 행사가 도면 하나를 같이 쓰면, 올해 도면에서 "1층"을 "지하 1층"으로 바꾸는 순간 **작년 예매 내역의 좌석 번호가 바뀝니다.**

**행사가 끝나면 도면은 고정됩니다.** 티켓(예매·초대권)이 걸린 좌석은 지울 수 없습니다. 취소·회수된 티켓만 남은 좌석·회차·구역은 지울 수 있지만 **기록으로 남아**, 그 티켓에는 원래 좌석·회차가 그대로 보입니다. 이 덕분에 티켓이 좌석을 가리키기만 해도 1년 뒤에 같은 번호가 나옵니다.

## 2층 — 재고

> **언제 몇 자리가 남았는가.**

```
행사
 └─ 날짜
     └─ 회차
```

**날짜가 회차보다 위에 있습니다.** 날짜를 가리켜야 하는 것이 셋 있기 때문입니다.

| | 무엇을 가리키나 |
|---|---|
| 1인 총 매수 "날짜별" (`06`) | 날짜마다 4매 |
| 운영 시간 (`02`) | 날짜마다 다름 — 주말은 늦게까지 |
| 묶음권 (`05`) | 날짜를 건너 묶음 |

### 회차형과 종일형은 "날짜 아래 회차가 몇 개냐"입니다

```
공연       3/14 ─ 15:00 회차 · 19:00 회차
전시       3/14 ─ 10:00~18:00 회차 하나
혼잡 전시   3/14 ─ 10-12시 · 12-14시 · 14-16시
페스티벌    5/3 ─ 종일 회차 하나
```

**혼잡 전시는 회차형입니다.** 재고가 시간으로 나뉘는 순간 회차형이고, 이게 `02`의 원래 정의입니다.

> 이전 `02`에는 "종일형 시간대 분할"이 있었습니다. 종일형의 정의가 "재고가 시간으로 나뉘지 않는 것"인데 시간으로 나누는 기능을 달아둔 **문서 내 모순**이었습니다. 삭제했습니다. 시간을 쪼개려면 회차형으로 등록합니다.

### 재고는 회차에만 붙습니다

| 구역 종류 | 회차가 가지는 것 |
|---|---|
| 지정형 | **좌석마다** 팔렸나 / 선점 중인가 / 판매 제외인가 |
| 수량형 | **정원과 잔여 숫자**, 관계자 확보 수 |

같은 좌석("1층 12열 7번")이 3/14 19시에는 팔렸고 3/15 19시에는 비어 있을 수 있습니다. 좌석은 하나, 판매 상태는 회차마다입니다.

### 판매 제외는 회차 단위입니다

좌석 속성 네 개는 성격이 둘로 갈립니다.

| 속성 | 어디에 붙나 | 왜 |
|---|---|---|
| 휠체어 · 시야제한 | **도면** | 물리적. 바뀌지 않음 |
| **판매 제외** | **회차** | 운영 판단. 회차마다 다름 |

첫 회차만 기자를 부르는 건 정상입니다. 도면 단위면 8회차 전부 빠집니다. 초대권도 회차 단위로 발권되므로 발권 단위와 맞습니다.

**"전 회차 일괄 적용" 버튼이 반드시 필요합니다.** 전 회차 같은 자리를 빼는 게 대부분인데, 없으면 8번 반복합니다.

## 3층 — 티켓

> **누가 어디에 들어갈 권리를 가졌는가.**

```
티켓
 ├─ 회차 1개 이상       묶음권은 N개
 ├─ 구역
 ├─ 좌석 0개 또는 1개   수량형은 없음
 ├─ 결제액 · 적용 할인
 ├─ 공제 면제 · 취소 시 배상
 ├─ 회차별 포기 표시      묶음권에서 출연자 변경으로 포기한 날
 ├─ 취소 시각 · 사유
 ├─ 티켓 번호            예매번호 + 순번
 ├─ QR 열쇠              추측 불가. 재발행하면 바뀜 → 공유 링크도 이걸로
 └─ 입장 기록 N개
```

**티켓이 "회차 1개 이상"을 가리키는 구조 하나로 셋이 설명됩니다.**

| | 회차 | 좌석 |
|---|---|---|
| 일반 지정석 | 1개 | 1개 |
| 일반 수량형 | 1개 | 없음 |
| 묶음권 | **N개** | 없음 |

### 묶음권 상품은 날짜를, 티켓은 회차를 가리킵니다

**주최자는 날짜만 고릅니다** ("5/3 · 5/4 · 5/5 3일권"). 날짜 아래 회차가 여럿이면 어느 회차로 들어갈지는 **관객이 예매할 때** 고르고, 그 회차들이 티켓에 붙습니다 (`05` 참조).

**출연자가 바뀐 날을 관객이 포기하면** 티켓은 그 회차를 계속 가리키고 **"포기" 표시**만 붙습니다 (`04`, `07` 참조). 검표가 "환불받은 날짜"를 알아보는 근거입니다.

| 행사 | 3일권이 묶는 것 |
|---|---|
| 페스티벌 (날짜당 회차 1개) | 5/3 · 5/4 · 5/5 — 자동으로 날짜가 묶임 |
| 혼잡 전시 (날짜당 회차 3개) | **관객이 날짜별로 시간대를 고름** |

검표 화면도 티켓이 가리키는 회차에서 나옵니다.

```
스탠딩A · 5/4 14-16시 입장분
3일권 (5/3~5/5) · 2일차
유효
```

**지정형은 묶음권이 불가합니다.** 날짜 수만큼 좌석을 동시에 선점해야 하고, 마지막 날 자리가 없으면 앞의 둘도 무의미해집니다 (`05` 참조).

# 티켓 상태와 입장 기록

## 티켓은 "취소됐나"만 기록합니다

**취소 시각과 취소 사유**를 남깁니다. 취소 시각이 비어 있으면 유효입니다.

| 취소 사유 |
|---|
| 관객 취소 · 좌석 변경 · 회차 취소 · 행사 취소 · 공연 중단 · 관리자 조치 · 초대권 회수 · 결제 오류 환불 |

각 사유가 언제 붙는지는 `07`에 있습니다.

사유를 티켓에 직접 적는 이유는 초대권 회수 때문입니다. 돈이 오가지 않아 환불 기록에서 사유를 읽을 수 없습니다.

**"입장 완료"는 상태가 될 수 없습니다.** 칸 하나에는 값 하나만 들어가는데 입장은 여러 번 일어납니다.

> 3일권으로 5/3에 들어가면 "입장 완료"입니다. 5/4에 또 들어가야 하는데 이미 사용됐습니다.
> 되돌리면 5/3에 들어간 사실이 지워집니다.

재입장을 켠 페스티벌도 같습니다. 세 번 들어왔는데 칸 하나에는 몇 번인지 담기지 않습니다.

## 입장은 기록으로 쌓입니다

```
티켓 #1 (3일권)   취소 시각 없음
 ├─ 입장 기록  5/3 10:12  정문
 └─ 입장 기록  5/4 11:40  정문
                              ← 5/5는 기록 없음 = 아직 안 옴
```

| 기록에 남는 것 | |
|---|---|
| 어느 회차에 입장했나 | |
| 시각 | |
| 입구 | 게이트별 분포에 쓰임 (`11`) |
| 검표 수단 | QR 스캔 / 수동 검색 |
| 강제 통과 여부 | 중복 스캔을 밀고 들어간 건 (`10`) |

재입장이나 강제 통과가 없으면 일반 티켓은 기록이 0개 또는 1개라 지금 화면과 똑같이 보입니다.

**입장 기록은 30일 후 소멸합니다** (`10` 참조). 지우는 이유는 용량이 아니라 **개인 동선**이기 때문입니다. 티켓에 "입장했음" 같은 요약도 남기지 않습니다 — 주최자의 입장률은 집계 숫자로 남습니다.

### 보존 기간이 층마다 다릅니다

```
예매 건 · 티켓    법정 5년 — "재화의 공급" 기록. 이후 누가 샀는지만 지움 (`11` 참조)
 └─ 입장 기록      행사 종료 30일 후 통째로 삭제 — 개인 동선
집계 숫자          영구
```

**티켓은 지우지 않습니다.** 예매 건에는 "165,000원 결제"만 있고 **무엇을 공급했는지는 티켓에 있습니다.** 용량도 문제가 아닙니다 — 5년 누적 75만 행, 300MB 안팎입니다.

**역할 분담** — 예매 건은 **결제 이력**을, 티켓은 **입장 권리**를 책임집니다.

## 저장하는 것과 계산하는 것

관객 화면의 티켓 상태는 **대부분 계산됩니다.**

| 화면에 보이는 것 | 무엇으로 판단하나 |
|---|---|
| 유효 | 취소 안 됨 + 회차가 아직 안 지남 |
| 입장 완료 | 입장 기록이 있음 |
| **공연 종료** | 회차 날짜가 지남 |
| 취소됨 · 사유 | 취소 시각이 있음 |

**"만료"를 저장하지 않습니다.** 회차 날짜를 보면 알 수 있습니다.

> 저장하면 **매일 자정에 티켓 전체를 뒤져서** 바꿔야 합니다. 그 작업이 한 번 실패하면 끝난 공연의 티켓이 유효한 채로 남습니다.
>
> 연기하면 되돌려야 합니다. 3/20을 3/27로 미뤘는데 이미 만료로 바꿔놨으면 수백 장을 다시 돌려야 합니다.
>
> 저장된 값과 날짜가 어긋나면 **어느 쪽을 믿을지** 알 수 없습니다.

같은 원칙이 행사에도 적용됩니다 — "매진"은 상태가 아니라 잔여가 0인 순간의 표시입니다 (`04` 참조).

### 판단은 스캔하는 순간 일어납니다

검표는 어차피 스캔할 때마다 서버에 물어봅니다. 그 순간 이것들을 봅니다.

```
QR 스캔
 ├─ 지금 유효한 QR 열쇠인가?   → 재발행 전 열쇠면 안내, 모르는 값이면 차단 (`07` 참조)
 ├─ 이 행사의 티켓인가?        → 아니면 차단
 ├─ 취소됐나?                → 차단
 ├─ 이 회차가 맞나?           → 틀리면 차단. 취소된 회차·포기한 날짜도 차단 (`10` 참조)
 ├─ 검표 시작 시각이 지났나?   → 아니면 차단 (`03` 참조)
 └─ 이미 입장 기록이 있나?     → 경고. 재입장 ON이면 정상 통과
```

**"만료"는 "이 회차가 맞나?"에 녹아 있습니다.** 끝난 회차의 티켓을 찍으면 "이 회차가 아니다"로 차단됩니다.

**티켓 상태를 바꾸는 예약 작업이 필요 없습니다.** 정해진 시각에 도는 일(알림 발송 `12`, 보관 기간이 지난 기록 삭제 `04`, 행사 상태 자동 전환 `04` 등)은 있지만, 어느 것도 티켓이 유효한지를 바꾸지 않습니다.

# 티켓의 부모 — 예매 건과 초대권

티켓은 **예매 건 또는 초대권** 중 하나에 속합니다.

```
예매 건 (관객이 결제)  → 티켓 N장
초대권 (주최자가 발권)  → 티켓 N장
```

**공통점은 "여러 장을 함께 발권했고 한 목록에서 나눠준다"까지입니다.** 그래서 `07`의 예매 카드 안 티켓 목록과 `09`의 단체 초대 링크 페이지가 **같은 모양**입니다. 보이는 장소는 다릅니다. 없어진 표를 회색으로 남기는 동작도 같습니다 — 예매는 "취소됨", 초대권은 "회수됨".

나머지는 다릅니다.

| | 예매 건 | 초대권 |
|---|---|---|
| 만든 사람 | 관객 | 주최자 |
| 결제·환불 | 있음 | 없음 (회수만) |
| 변경 | 가능 | 불가 |
| 매수 제한 | 포함 | 미포함 |
| 집계 | **판매** | **초대** |
| 보이는 곳 | 마이페이지 예매 내역 | **링크 페이지만** |

**예매 내역에는 내가 돈을 내고 산 표만 나옵니다.** 초대권과 친구에게 공유받은 표는 받은 사람이 가입해 있어도 예매 내역에 나오지 않습니다. 계정에 담으면 같은 표 한 장이 두 계정에 보여 누구 표인지가 흐려집니다 (`07` · `09` 참조).

## 예매 건은 결제 단위입니다

```
예매 건 (예매번호 ...0091)
 ├─ 티켓 #1
 ├─ 티켓 #2
 └─ 결제·환불 내역
     ├─ 3/1  결제  165,000원
     ├─ 3/5  환불  −70,000원
     └─ 3/5  결제   80,000원
```

**예매 건에 취소 상태를 두지 않습니다.** 결제가 어디까지 왔는지만 있고 (`06` 참조), "부분 취소됨"을 만들면 4매 중 1매·2매·3매 취소가 전부 같은 상태가 되어 정보를 담지 못합니다. 무엇이 취소됐는지는 티켓 하나하나가 말해줍니다.

**취소된 티켓도 예매 카드에 회색으로 남습니다** (`07` 참조). 주최자가 회차를 취소하는 등 관객이 직접 하지 않은 취소를 예매 내역만 열어도 알 수 있습니다. 카드에는 실 결제액만 두고, 자세한 돈 흐름은 결제·환불 내역에서 봅니다.

## 변경은 티켓을 바꿔치웁니다

> **변경 = 기존 티켓 취소(환불) + 새 티켓 발급(결제)**

```
10만원 S석 → 8만원 A석

환불   −100,000원     관람 10일 전이라 공제 0%
결제     80,000원     새 티켓 가격 전액
```

**티켓에 "변경됨" 상태를 따로 두지 않습니다.** 취소된 티켓 하나와 새 티켓 하나이고, 둘을 잇는 이력은 **예매 건의 결제·환불 내역**이 가집니다.

이 방식의 이점이 셋 있습니다.

- **티켓 금액이 곧 실제 받은 돈**입니다. 차액만 정산하면 새 티켓에는 8만원이 적혀 있는데 실제로는 2만원이 환불됐을 뿐이라 어긋납니다
- 기존 티켓의 환불은 **지금 취소하는 것과 같은 금액**입니다. 관람 임박이면 공제가 붙습니다 (`08` 참조)
- `08`의 "변경은 취소 후 재예매와 같다"가 계산뿐 아니라 **실제 처리도 그렇게** 됩니다

**관객에게 미리 알려야 합니다.** 카드에 환불과 결제가 각각 찍힙니다.

> 기존 예매는 환불되고 새로 결제됩니다. 카드 내역에 환불과 결제가 각각 표시됩니다.

# 선점

예매 건이 만들어지기 **전**에 존재합니다. 좌석 선택 화면에 들어가는 순간 생깁니다 (`06` 참조).

```
선점 (10분)
 ├─ 좌석 N개  또는  구역 + 수량
 ├─ 조기예매 몫 N개
 └─ 가격
```

**셋을 한 묶음으로 잠급니다.** 그래야 조기예매가가 3만원인 걸 보고 고른 사람이 결제하는 사이 소진돼도 3만원으로 삽니다.

**만료는 선점의 일입니다.** `06`의 예매 건 상태에 있던 "만료"는 선점 쪽으로 옮깁니다. 결제창을 열기 전에 타이머가 끝나면 예매 건은 아직 없습니다.

## 조기예매 몫은 돌아오지 않습니다

> **선점하는 순간 누적으로 센다. 결제 여부와 무관하게 돌아오지 않는다.**

복구하면 선착순이 깨집니다.

```
1. 조기예매 30개가 선점으로 전부 잡힘
2. A가 들어옴 → "조기예매 마감" → 정가 5만원 결제
3. 10분 뒤 25개가 만료되어 복구된다면
4. B가 들어옴 → 조기예매 3.5만원 결제

A가 먼저 왔는데 1.5만원을 더 냈습니다.
```

`05`가 피하려 한 "마감됐던 게 다시 열리는 이상한 순간"이 바로 이것입니다.

**세는 값은 하나뿐이고 줄어들지 않습니다.**

**감수하는 것** — 선점만 하고 버리면 몫이 사라집니다. `05`가 이미 같은 성격의 손실을 감수하고 있고(취소분 미복구), `06`에 방어선이 있습니다 — 한 번에 선점 가능한 건 1회 선택 매수(기본 4석)까지, 타이머는 화면 진입부터 돕니다.

# 무엇이 무엇을 가리키나

| 이것은 | 이것을 가리킨다 |
|---|---|
| 소유자 · 운영자 | 주최자 (한 사람이 여러 주최자에 소속 가능) |
| 행사 | 주최자 |
| 소속 | 운영진(사람) + 주최자 + 역할 + 기간 |
| 주최자명 변경 이력 | 주최자 |
| 날짜 | 행사 |
| 회차 | 날짜 |
| 블록 · 구역 · 입구 | 행사 (도면) |
| 좌석 | 블록 + 구역 |
| 좌석 판매 상태 | 회차 + 좌석 |
| 묶음권 상품 | 날짜 N개 |
| 조기예매 · 쿠폰 | 행사 |
| 선점 | 관객 + 회차 + (좌석들 또는 수량) |
| 예매 건 | 관객 |
| 초대권 | 주최자 + 회차 1개 이상 (묶음권 초대는 N개) |
| **티켓** | **예매 건 또는 초대권 + 회차 N개 + 구역 + 좌석 0~1개** |
| 입장 기록 | 티켓 + 회차 + 입구 |
| 티켓 없는 입장 기록 | 회차 + 입구 + 처리한 운영진 |
| 결제·환불 내역 | 예매 건 + 티켓들 |
| 공유 링크 | 티켓 (QR 열쇠로 만듦) |
| QR 재발행 기록 | 티켓 + 옛 QR 열쇠 |
| 장소 변경 재배정표 | 행사 + 티켓 + 옛 좌석 · 새 좌석 |
| 미수금 | 주최자 |
| 검표 계정 | 행사 |
| 변경 이력 | 행사 |

### 무엇을 가리키고 무엇을 직접 갖나

> **바뀌면 따라 바뀌어야 하는 것은 가리킨다. 바뀌어도 그대로여야 하는 것은 직접 갖는다.**

| 티켓이 가리킴 | 티켓이 직접 가짐 |
|---|---|
| 회차 — 연기하면 날짜가 따라 바뀜 | 결제 금액 — 가격을 바꿔도 산 표는 그대로 |
| 좌석 — 블록 이름을 고치면 표기가 따라 바뀜 | 받은 할인 — 조기예매가 끝나도 남음 |
| 구역 | 공제 면제 · 취소 시 배상 · 취소 시각 · 취소 사유 · QR 열쇠 |

블록 이름을 고치거나 회차를 연기해도 **티켓은 하나도 손대지 않습니다.** (예외: 장소 변경으로 도면을 바꿀 때 좌석을 새 도면으로 재배정, `04` 참조) 화면을 그릴 때 티켓 → 좌석 → 블록, 티켓 → 회차 → 행사로 따라가 읽어옵니다. 한 사람의 예매 내역은 많아야 수십 장이라 부담이 되지 않습니다.

## 티켓 번호

지정석은 좌석 번호로 구분되지만 수량형은 자리가 없습니다. **예매번호(초대권은 초대권 번호) + 순번**을 씁니다.

```
스탠딩A · 0091-2
```

**유일성이 공짜로 따라옵니다.** 예매번호가 이미 유일하므로 값을 뽑고 중복을 확인하는 작업이 없습니다. 분모가 없으니 부분 취소에도 번호가 바뀌지 않고, 같은 행사를 두 번 예매해도 `0091-1`과 `0134-1`로 갈립니다.

**번호에 부모가 드러납니다.** 어느 예매의 몇 번째 장인지 보여, 문의할 때 관객과 주최자가 같은 걸 가리킵니다. 랜덤 값은 그게 안 됩니다.

초대권도 같습니다 — 초대권 번호 + 순번.

**예매번호 자체는 추측할 수 없어야 합니다.** 순차 번호면 `0091`에서 "91건 팔렸다"를 추측할 수 있어, 주최자만 보는 판매 현황(`11`)이 번호로 새어나갑니다.

**티켓 번호와 QR 열쇠는 다릅니다.** 번호는 화면에 보이는 이름표, 열쇠는 검표용 비밀 값입니다 (`07` 참조).

# 이 문서를 그리면서 고친 것

| | 전 | 후 |
|---|---|---|
| **날짜 층** | 행사 → 회차 | 행사 → **날짜** → 회차 |
| **도면** | 회차 아래에 구역·좌석 | **행사에 하나.** 재고만 회차별 |
| **종일형 시간대 분할** | 종일형에 슬롯 기능 | **삭제.** 시간을 쪼개면 회차형 |
| **묶음권** | 종일형 수량형 전용, 날짜를 묶음 | **수량형 전용.** 상품은 날짜를, 티켓은 회차를 가리킴 |
| **티켓 상태** | 유효 / 취소됨 / 입장 완료 | **취소 시각 · 사유** + 입장 기록 분리 |
| **판매 제외** | 좌석 속성 (도면) | **회차 단위** |
| **변경** | 차액만 정산 | **기존 티켓 환불(공제 규정대로) + 신규 결제** |
| **조기예매 몫** | 소진 후 영구 마감 (선점 만료는 미정의) | **선점 순간 누적.** 어떤 경우에도 미복구 |
| **수량형 표기** | 스탠딩A · 3/4 | **스탠딩A · 0091-2** (예매번호 + 순번) |
| **예매 건 "만료" 상태** | 예매 건이 가짐 | **선점이 가짐** |
| **도면 공유** | 미정의 | **행사마다 따로.** 복제는 통째로 복사 |
| **예매 카드** | 남은 티켓만 | **취소된 티켓도 회색 + 사유** |
| **초대권·공유받은 표** | 미정의 | **예매 내역에 안 나옴.** 링크 페이지에서만 |
| **QR** | 티켓 번호를 담음 | **QR 열쇠를 담음.** 재발행하면 열쇠만 바뀜 |
| **티켓 없는 입장** | 기록 위치 미정의 | **회차에 기록.** 이름 없이 인원·사유·처리자 |

**모순이었던 것 세 개** — 종일형 시간대 분할(정의와 충돌), 티켓 "입장 완료" 상태(묶음권·재입장이 깨짐), 도면이 회차 아래 있는 구조(기본가 하나와 충돌).

나머지는 정의되지 않았던 구멍입니다.
