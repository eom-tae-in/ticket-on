# 00. 범위와 용어

## 서비스 정의

> 소규모 주최자가 좌석 배치도를 직접 만들고, 관객이 원하는 자리를 골라 예매하는 웹 서비스.

대형 예매처에 입점하기 부담스러운 주최자가 대상입니다. 소극장, 대학 공연, 독립 음악가, 동호회 정기공연 같은 규모.

## 전제

| 항목 | 값 |
|---|---|
| 예상 이용자 | 1만 명 이하 |
| 형태 | 웹 서비스 |
| 대상 행사 | 공연, 전시, 페스티벌 |
| 결제 | PG 테스트 모드 (토스페이먼츠·카카오페이·포트원 등) |

**결제는 테스트 모드**입니다. 실제 돈은 빠져나가지 않지만 승인·취소·실패 세 흐름을 모두 구현합니다. 정산 기능은 화면상 존재하되 실제 송금은 없습니다.

**본인확인은 하지 않습니다.** 휴대폰 본인확인은 본인확인기관과의 계약이 필요해 테스트 결제 환경과 맞지 않습니다. 이름·생년월일·전화번호는 본인이 직접 입력한 값이라 검증되지 않습니다 (`01` 참조).

**전화번호는 인증하지 않되, 관객이 본인 번호를 정확히 적는다고 가정합니다.** 이 전제 위에서 **번호 하나에 계정 하나**만 만들 수 있습니다. 매수 제한과 이용 정지가 사실상 사람 단위로 걸리는 근거입니다 (`01` 참조).

**단계를 나누지 않습니다.** 이 문서는 MVP나 2단계가 아니라 **완성형 설계**입니다. 만들기로 한 것은 전부 만들고, 만들지 않기로 한 것은 이유와 함께 `99`에 적혀 있습니다.

## 규모가 설계에 미치는 영향

- **대기열 같은 트래픽 장치는 불필요합니다.** 오픈 시점에 몰려도 정책(매수 제한)으로 풉니다
- **"소규모 주최자가 직접 다루기 쉬운가"가 설계의 축입니다.** 기능 수보다 주최자가 30분 안에 행사를 열 수 있는지가 중요합니다

## 사용자 역할

| 역할 | 핵심 관심사 |
|---|---|
| 관객 | 좋은 자리를 빠르고 확실하게 잡는 것 |
| 주최자 운영진 (소유자·운영자) | 행사 등록이 쉬울 것, 얼마나 팔렸는지 보일 것, 여러 명이 함께 운영할 수 있을 것 |
| 현장 스태프 | 입장할 때 티켓이 진짜인지 빨리 확인 |
| 플랫폼 관리자 | 주최자 승인, 정지, 분쟁 처리 |

## 기기 전제

| 영역 | 우선 |
|---|---|
| 관객 (목록·예매·티켓) | **모바일 우선** |
| 검표 | **모바일·태블릿** |
| 주최 관리 | 데스크톱 우선, 현황 확인은 모바일도 |
| 좌석 배치도 에디터 | 데스크톱 우선, 모바일은 기본 조작까지 |

**티켓 QR은 100% 폰으로 보여줍니다.** 검표도, 초대권 링크도 모바일입니다.

## 현장 환경 전제

> **검표 현장은 전원과 인터넷이 있다고 가정합니다.**

오프라인 검표도, 예매자 명단 내려받기도 만들지 않습니다. 대신 **관객에게 QR 미리 저장을 안내**합니다. 그래도 끊기면 테더링 같은 현장 대응에 맡깁니다 (`10` 참조).

## 용어

| 용어 | 뜻 |
|---|---|
| **주최자** | 행사를 여는 **단체**. 심사·정지·정산의 단위 (`01` 참조) |
| **소유자 · 운영자** | 주최자에 소속된 사람. 소유자 1명, 운영자 여러 명. 둘을 합쳐 **운영진** (`01` 참조) |
| **주최자 페이지** | 주최자의 공개 페이지. 소개 · 운영진 · 진행 중 · 지난 행사 (`01` 참조) |
| **운영진 프로필** | 운영진의 공개 페이지. 닉네임 · 소개 · 참여한 주최자. 관객에게는 없음 (`01` 참조) |
| **행사** | 주최자가 여는 하나의 공연·전시·페스티벌. 주최자에 속한 데이터 |
| **도면** | 블록·좌석·구역·입구. **행사에 하나** (`02` 참조) |
| **날짜** | 행사가 열리는 하루. 회차의 상위 단위 |
| **회차** | 관객이 고르는 "언제"의 단위. **재고가 붙는 유일한 곳** |
| **유형** | 공연 · 전시 · 페스티벌. 카테고리 목록을 정함 (`03` 참조) |
| **회차 방식** | 회차형 / 종일형 — 날짜 아래 회차가 여러 개인가 하나인가 (`02` 참조) |
| **구역** | **가격**이 붙는 재고 묶음 (R석, 스탠딩A) |
| **지정형 / 수량형** | 구역이 좌석을 고르는가, 매수만 고르는가 (`02` 참조) |
| **블록** | 좌석 **번호**를 매기는 물리적 덩어리 (1층, 2층) |
| **좌석** | 지정형 구역 안의 개별 자리 |
| **티켓** | QR 1개 = 입장 1명 (`07` 참조) |
| **QR 열쇠** | 티켓이 가진 추측 불가 값. QR과 공유 링크를 만듦. 재발행하면 바뀜 (`07` 참조) |
| **입장 기록** | 티켓에 쌓이는 입장 이력. 회차·시각·입구 |
| **예매 건** | 한 번의 결제 단위. 티켓 N장을 가짐 |
| **예매번호** | 예매 건의 번호. 추측할 수 없게 발급 (`07` 참조) |
| **선점** | 결제 전 10분간 재고를 잠그는 것 (`06` 참조) |
| **조기예매** | 수량과 기간이 한정된 할인 |
| **쿠폰** | 코드를 입력해 적용하는 할인 |
| **묶음권** | 여러 날짜를 묶어 파는 상품 (수량형 전용, `05` 참조) |
| **불가항력** | 천재지변, 정부의 공연 금지 조치. 취소·중단 때 10% 배상이 없음 (`04` 참조) |
| **공제 면제** | 주최자 쪽 변경(연기·장소·시간·출연자)으로 티켓에 붙는 권리. 언제 취소해도 공제 0% (`04` 참조) |
| **판매 제외 · 관계자석** | 팔지 않고 빼둔 좌석·수량. 초대권에 씀 (`09` 참조) |
| **초대권** | 결제 없이 주최자가 발권하는 묶음. **예매 건처럼 티켓 N장을 가짐** (`09` 참조) |
| **입구** | 검표가 이루어지는 게이트 |

관객 화면에서는 유형에 따라 "공연", "전시", "페스티벌"로 부릅니다. 주최자 화면에서는 전부 **"행사"** 로 통일합니다.

## 의도적으로 범위 밖에 둔 것

`99-decisions.md`에 이유와 함께 정리되어 있습니다. 주요 항목:

- 현장 체류 인원 관리 (퇴장 스캔), 오프라인 검표
- 대기열 시스템, 추첨 예매
- 증빙이 필요한 할인 (학생·청소년·경로 등)
- 휴대폰 본인확인, 성별 수집
- 티켓 양도, 리뷰·후기, 웹 푸시
- 다국어, 대리 예매
- 실제 정산 송금, 세금계산서
