# 12. 알림 · 통지

## 원칙

> **긴급하거나 돈이 걸린 것만 문자. 나머지는 이메일.**

문자는 비용이 들고 쌓이면 알림 피로가 됩니다.

## 전달 수단과 알림함

| 수단 | 역할 |
|---|---|
| **이메일 · 문자** | 실제 전달 |
| **서비스 내 알림함** | **기록 보관** — 보낸 알림이 여기에도 쌓임 |

**서비스 내 알림만으로는 안 됩니다.** 웹이라 사용자가 사이트에 들어와야 보거든요. 예매를 마치고 나가면 공연 날까지 몇 주 동안 안 들어옵니다. 전날 리마인더를 알림함에만 넣어두면 아무도 못 봅니다.

**알림함은 "언제 취소 안내가 왔더라"를 다시 확인하는 곳**입니다. 이메일을 지웠거나 문자를 놓쳤을 때 들어와서 봅니다. 전달 수단을 늘리는 게 아니라 **같은 내용을 한 벌 더 쌓아두는 것**입니다.

**읽은 것과 안 읽은 것은 알림함 목록 안에서만 구분합니다.** 알림함을 열어 **처음 본 순간 읽음**이 됩니다. 그래서 "지난번에 본 뒤 새로 온 것"만 굵게(점 표시) 보이고, 다음에 열면 보통 글자로 돌아갑니다. **탭에 숫자 배지는 달지 않습니다** — 문자·이메일로 이미 받은 알림까지 "안 읽음"으로 쌓여 숫자가 의미를 잃습니다.

**웹 푸시는 만들지 않습니다.** 허용률이 낮고(대개 10~20%), iOS는 홈 화면에 추가해야 동작하며, 가입 직후 권한 팝업은 그 자체가 이탈 요인입니다.

**초대권 받는 사람**에게도 회차 취소·행사 취소·공연 중단·연기·회차 시간 변경·장소 변경·출연자 변경이 갑니다. 발권할 때 문자나 이메일로 보낸 경우 **같은 수단**으로 갑니다. 링크만 복사한 초대권은 우리가 연락할 수 없어 주최자 화면에 "직접 알려야 할 초대권"으로 띄웁니다 (`09` 참조).

**전날 리마인더를 문자로 하는 게 효과가 큽니다.** 노쇼를 눈에 띄게 줄입니다. 이메일은 안 봅니다.

**예매 완료 문자에는 티켓 링크**를 넣습니다. 관객이 바로 저장할 수 있어야 합니다.

### 전날 리마인더

**발송 시각은 낮 12시**입니다. 점심시간이라 확인율이 높습니다.

**묶음권은 날짜마다 보냅니다.** 3일권이면 3번입니다. 첫날만 보내면 나머지를 잊습니다.

**QR 미리 저장 안내**를 함께 넣습니다 (`10` 참조).

## 주최자 대상

전부 이메일입니다. 급한 게 없습니다.

| 이벤트 |
|---|
| 승인 / 반려 |
| 정지 통지 · 해제 ("판매를 재개할 수 있습니다") |
| 장소·일시 변경 승인 / 반려 |
| 정산 완료 (미수금이 있으면 함께 표시) |
| 불가항력 확인 결과 (배상 면제 / 지급) |
| 작성 중 행사 30일 미수정 |
| **수정 요청** (관리자 조치, 기한 포함) — 신고 접수 자체는 알리지 않음 (`01` 참조) |
| 행사 페이지 내리기 · 다시 올리기 (관리자 조치) |
| 공연 지연 · 출연자 변경을 관리자가 대신 처리함 |
| 운영자 초대 (받는 사람에게) |
| 운영진에서 내보내짐 (그 사람에게) |
| **소유자 변경** (운영자 전원에게) |
| 정산 계좌 변경 확인 결과 (소유자에게) |
| 주최자명 변경 (운영진 전원에게) |
| **운영자가 행사 제목을 바꿈** (소유자에게) — 승인이 아니라 알림 |
| 다시 열기 승인 / 반려 |
| 닉네임 · 소개가 초기화됨 (그 사람에게, 관리자 조치) |
| 주최자 로고가 초기화됨 (운영진 전원에게, 관리자 조치) |

**받는 사람** — 주최자에 관한 알림은 **소유자와 운영자 전원**에게 갑니다. 정산 계좌처럼 소유자만 다루는 일은 소유자에게만 갑니다.

**주최자 쪽 메일 제목에는 `[주최]` 접두사**를 붙입니다. 같은 이메일로 사용자 계정과 주최자 쪽 로그인을 둘 다 만들 수 있어 메일함이 섞이기 때문입니다 (`01` 참조).

## 관리자 대상

알림 대신 **처리 목록**으로 받습니다 (`13` 참조). 아래가 목록에 쌓이고, 공연이 임박한 건은 강조합니다.

- 주최자 신청 (같은 소유자·단체명의 닫힌 주최자 함께 표시) · 다시 열기 신청 · 소유자 이전 신청
- 주최자명 변경 (사후 확인용. 사칭이면 신고·정지로 처리)
- 장소·일시 변경(연기) 승인 요청
- 정산 계좌 변경 확인 · 미수금 납부 확인
- QR 재발행 신청
- 신고 (공연 지연 · 출연자 변경 신고 포함) · 수정 요청에 대한 [수정 완료] 확인
- 불가항력 확인 (정산 기한이 다가오면 강조)
- 예매 대신 취소 문의 (오류 구제, `08` 참조)

**소유자가 바뀌면 관리자에게도 알립니다** (`01` 참조).

## 검표 계정

**알림이 없습니다.** 이메일도 전화번호도 없는 계정입니다 (`01` 참조).

## 알림 설정

마이페이지에 둡니다.

> **알림 설정**
> ☑ 예매·취소 확인
> ☐ 공연 전날 리마인더
> ☑ 예매 오픈 알림
>
> **마케팅 수신** (선택)
> ☐ 신규 행사 소식
> *2026-03-01 동의 · 언제든 철회할 수 있습니다*

**계정 단위 설정**입니다. 행사마다 토글을 두면 10개 예매한 사람은 10번 꺼야 합니다.

### 해제할 수 없는 알림은 목록에 넣지 않습니다

**행사 변경·취소·연기·장소 변경·시간 변경·출연자 변경·공연 중단 안내는 조건 없이 발송**되며, 설정 화면에 나타나지 않습니다.

토글이 안 눌리는 걸 보여주면 "왜 못 끄냐"는 문의만 생깁니다. 그건 안내가 아니라 고지 의무에 가깝습니다. 장소가 바뀌었는데 못 받으면 관객이 엉뚱한 데로 갑니다.

### 마케팅 수신은 구분해서 표시

위는 **거래 알림**이라 받는 게 기본이고, 아래는 **법적 동의 항목**이라 동의 일시를 기록해둬야 합니다. 분쟁이 생기면 "언제 동의했나"가 근거가 됩니다.

**가입 때 받은 동의를 언제든 철회할 수 있어야** 합니다.

## 마케팅 발송

**관리자가 동의한 사람에게 신규 행사 소식을 이메일로 보냅니다.** 문자는 쓰지 않습니다.

받아두기만 하고 보내지 않으면 가입 체크박스와 설정 스위치가 아무 일도 하지 않게 되므로, 동의를 받는 이상 보내는 기능까지 둡니다.

**법(정보통신망법)이 요구하는 것** — 보내는 이상 다음을 지켜야 합니다.

| | |
|---|---|
| 제목 | **"(광고)"** 로 시작 |
| 본문 | 보낸 곳 이름·연락처, **수신 거부 링크** |
| 동의·거부·철회 | 처리 결과를 **14일 안에** 그 사람에게 알림. 이 알림에는 광고를 넣지 않음 |
| 재확인 | **동의한 날부터 2년마다** 안내. 보낸 곳 · 동의한 날짜 · **철회 방법**을 담음. **응답이 없으면 동의 유지** (`99` A-6) |

**재확인 안내는 "계속 받으려면 클릭"이 아니라 "그만 받으려면 여기"로 보냅니다.** 앞의 방식이면 응답하지 않은 사람을 철회로 처리해야 합니다.

**밤 시간 제한은 걸리지 않습니다.** 밤 9시~아침 8시 광고 전송 제한은 문자·앱 푸시·전화에 해당하고 이메일은 빠집니다. 문자로는 광고를 보내지 않습니다.

**수신 거부 링크는 로그인 없이** 한 번에 처리돼야 합니다. 로그인을 요구하면 거부가 어려워져 문제가 됩니다.

## 전화번호는 인증하지 않습니다

**관객이 본인 번호를 정확히 적는다고 가정합니다** (`01` 참조). 문자 인증번호는 건마다 비용이 들어 받지 않습니다.

그래도 오타는 생길 수 있어 **문자가 잘못된 번호로 갈 수 있습니다.** 틀리게 적으면 본인이 알림을 못 받으니 대부분 제대로 적습니다. 문자가 실패해도 **알림함에는 그대로 남습니다.**

**긴급 통지는 이메일과 문자를 모두 보내므로** 한쪽이 실패해도 전달될 가능성이 남습니다.
