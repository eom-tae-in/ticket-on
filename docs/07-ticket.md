# 07. 티켓 · QR · 공유

여러 문서가 이 개념을 전제합니다. `02`와 함께 먼저 읽으십시오.

## 기본 원칙

> **티켓 1장 = QR 1개 = 입장 1명**

4매를 예매하면 티켓 4장, QR 4개입니다. 수량형 2매도 티켓 2장입니다.

**이유는 검표에 있습니다.** QR 하나로 4명을 처리하면 일행이 따로 올 때 방법이 없습니다. 먼저 온 사람이 찍는 순간 4명 전부 입장 처리되고, 나중에 온 사람은 "이미 입장"으로 막힙니다.

## 예매 건과 티켓은 다릅니다

```
예매 건 (결제 단위 · 예매번호 ...0091)
 ├─ 티켓 #1  R석 12열 7번  → QR
 ├─ 티켓 #2  R석 12열 8번  → QR
 ├─ 티켓 #3  R석 12열 9번  → QR
 └─ 티켓 #4  R석 12열 10번 → QR
```

| | 단위 |
|---|---|
| 결제·환불 | 예매 건 |
| 검표 | **티켓** |
| 취소·변경 | **티켓** (부분 가능) |
| 할인 기록 | **티켓** (`05` 참조) |

### 티켓이 직접 갖는 것과 가리키기만 하는 것

> **바뀌면 티켓도 따라 바뀌어야 하는 것은 가리킨다.**
> **바뀌어도 티켓은 그대로여야 하는 것은 직접 갖는다.**

| | 티켓이 | 왜 |
|---|---|---|
| 회차 | 가리킴 | **연기하면 티켓 날짜도 따라 바뀌어야 함** (`04` 참조) |
| 좌석 | 가리킴 | 블록 이름 오타를 고치면 티켓 표기도 따라 바뀌어야 함 (`02` 참조). 장소 변경으로 도면이 바뀌면 새 좌석을 가리킴 (`04` 참조) |
| 구역 | 가리킴 | "R석" 표기가 바뀌면 따라감 |
| **결제 금액** | **직접 가짐** | 주최자가 가격을 바꿔도 이미 산 표는 그대로여야 함 |
| **받은 할인** | **직접 가짐** | 조기예매가 끝나도 그때 받은 할인은 남아야 함 |
| **공제 면제 · 취소 시 배상** | **직접 가짐** | 그 티켓에만 붙는 권리. 연기·장소 변경·시간 수정·출연자 변경 때 붙음 (`04` 참조) |
| **회차별 포기 표시** | **직접 가짐** | 묶음권에서 출연자가 바뀐 날을 포기했을 때, 그 회차에 붙음 (아래) |
| **취소 시각 · 사유** | **직접 가짐** | |
| **QR 열쇠** | **직접 가짐** | 추측할 수 없는 값. 재발행하면 바뀜 (아래 참조) |

그래서 블록 이름을 고치거나 회차를 연기해도 **티켓은 하나도 손대지 않습니다.** 이름과 날짜는 한 곳에만 있고, 화면을 그릴 때 티켓에서 좌석·회차로 따라가 읽어옵니다.

**이게 안전한 전제가 둘 있습니다** — 티켓(예매·초대권)이 걸린 좌석은 지울 수 없고, 행사가 끝나면 도면을 고칠 수 없습니다 (`04` 참조). 취소·회수된 티켓만 남은 좌석은 지울 수 있지만, 지워도 기록으로 남아 그 티켓에는 원래 번호가 그대로 보입니다. 그래서 1년 뒤에 봐도 같은 좌석 번호가 나옵니다.

**예외는 하나입니다** — 첫 회차 전에 배치가 다른 곳으로 장소를 옮기면, 관리자 승인을 거쳐 좌석이 있는 티켓(예매·초대권)이 새 도면의 좌석을 가리키게 됩니다. 옛 좌석은 재배정표로 남습니다 (`04` 참조).

## 티켓은 "취소됐나"만 기록합니다

"유효 / 취소됨" 중에 고르는 칸 대신 **취소 시각과 취소 사유**를 남깁니다.

| 취소 시각 | 뜻 |
|---|---|
| 비어 있음 | 유효 |
| 3/5 14:20 | 그 시각에 취소됨 |

| 취소 사유 | 언제 |
|---|---|
| 관객 취소 | 관객이 직접 |
| 좌석 변경 | 변경으로 기존 티켓이 바뀔 때 (`08`) |
| 회차 취소 | 주최자가 회차를 취소 (`04`) |
| 행사 취소 | 주최자의 행사 취소, 관리자 정지 3단계 (`04`, `01`) |
| 공연 중단 | 예정 시간의 절반 이하만 하고 멈춤 (`08`) |
| 관리자 조치 | 오류로 기한 안에 못 한 취소를 관리자가 대신 (`08`) |
| 초대권 회수 | 주최자가 초대권을 회수 (`09`) |
| 결제 오류 환불 | 승인은 났는데 좌석 확정이 안 된 경우 (`06`) |

**정지 3단계도 사유는 "행사 취소"입니다.** 관객 입장에서는 같은 일이고, 주최자 자발적 취소인지 관리자 강제 취소인지는 주최자 이력에 따로 남습니다 (`04` 참조).

**사유를 티켓에 직접 적는 이유** — 환불 기록에서 사유를 읽을 수도 있지만, 초대권 회수는 돈이 오가지 않아 환불 기록이 없습니다. 모든 취소에 사유가 붙으려면 티켓에 있어야 합니다.

**"입장 완료"는 상태가 아닙니다.** 칸 하나에는 값 하나만 들어가는데 입장은 여러 번 일어납니다.

> 3일권으로 5/3에 들어가면 "입장 완료"입니다. 5/4에 또 들어가야 하는데 이미 사용됐습니다.
> 되돌리면 5/3에 들어간 사실이 지워집니다.

재입장을 켠 페스티벌도 같습니다 (`03` 참조). 세 번 들어왔는데 칸 하나에는 몇 번인지 담기지 않습니다.

**"만료"도 상태가 아닙니다.** 회차 날짜를 보면 끝났는지 알 수 있습니다. 저장해두면 매일 자정에 티켓 전체를 뒤져 바꿔야 하고, 연기로 날짜가 바뀌면 수백 장을 되돌려야 합니다 (`14` 참조).

## 입장은 기록으로 쌓입니다

```
티켓 #1 (3일권)   취소 시각 없음
 ├─ 입장 기록  5/3 10:12  정문
 └─ 입장 기록  5/4 11:40  정문
                              ← 5/5는 기록 없음 = 아직 안 옴
```

| 기록에 남는 것 | |
|---|---|
| 어느 회차에 입장했나 | |
| 시각 | |
| 입구 | 게이트별 분포에 쓰임 (`11`) |
| 검표 수단 | QR 스캔 / 수동 검색 |
| 강제 통과 여부 | 중복 스캔을 밀고 들어간 건 (`10`) |

재입장이나 강제 통과가 없으면 **일반 티켓은 기록이 0개 또는 1개**라 화면에 보이는 모습은 똑같습니다.

### 입장 기록은 30일 후 소멸합니다

```
티켓 (금액 · 좌석 · 취소 여부)   5년 보존 → 이후 누가 샀는지만 지움 (`11` 참조)
입장 기록                        행사 종료 30일 후 통째로 삭제
집계 숫자                        영구 보존
```

**티켓에 "입장했음" 같은 요약도 남기지 않습니다.** 누가 보는지 따져보면 필요가 없습니다.

| 누가 | 무엇을 | 언제 |
|---|---|---|
| 관객 | "입장 완료" 표시 | 행사 당일~직후 |
| 주최자 | 입장률 · 게이트별 분포 | 당일, 다음 행사 준비할 때 → **집계 숫자로 충분** |
| 분쟁 | "저 들어갔는데요" → 시각과 입구 | 행사 후 며칠 |

**1년 전 공연에 "입장 완료"가 붙어 있을 필요가 관객에게 없습니다.** 주최자의 입장률은 집계로 이미 남습니다 (`11` 참조).

**"사용됨"이나 "만료"는 어느 시점에도 필요 없습니다.**

### 관객 화면의 표시는 계산됩니다

| 보이는 것 | 무엇으로 판단하나 |
|---|---|
| 유효 | 취소 안 됨 + 회차가 아직 안 지남 |
| 입장 완료 | 입장 기록이 있음 |
| 공연 종료 | 회차 날짜가 지남 |
| 취소됨 · 사유 | 취소 시각이 있음 |

**예매 건에는 취소 상태를 두지 않습니다.** 결제가 어디까지 왔는지(결제 대기·완료 등)만 있고 (`06` 참조), "부분 취소됨" 같은 상태를 만들면 4매 중 1매·2매·3매 취소가 전부 같은 상태가 되어 정보를 담지 못합니다. 무엇이 취소됐는지는 티켓 하나하나가 말해줍니다.

## 취소된 티켓도 예매 카드에 남습니다

**예매 카드**는 예매 내역에서 행사 하나를 보여주는 카드입니다. 안에서 예매 건별로 나뉩니다 (`13` 참조).

```
○○밴드 단독공연 · 3월 14일 19:00
총 3장                                  ← 유효한 것만 셈

┌─ 예매번호 ...0091 · 3/1 예매 ─────────────┐
│  R석 12열 7번    [QR] [공유]                │
│  R석 12열 8번    [QR] [공유]                │
│  A석 15열 3번    [QR] [공유]                │
│  ─────────────────────────                 │
│  R석 12열 9번    취소됨 · 관객 취소          │  ← 회색, 버튼 없음
│  R석 12열 10번   취소됨 · 좌석 변경          │
│                                            │
│  실 결제액 145,000원      [결제·환불 내역]   │
└──────────────────────────────────────┘
```

**유효한 티켓은 위에, 취소된 티켓은 아래에 회색으로** 둡니다. 취소된 티켓에는 QR·공유 버튼이 없습니다.

**사라지게 하지 않는 이유가 셋입니다.**

- **관객이 직접 하지 않은 취소** — 주최자가 회차를 취소하거나 관리자가 정지하면 관객은 아무것도 안 했는데 표가 없어집니다. 알림 열람률이 30% 안팎이라 (`04` 참조) 못 본 관객은 "내 표 어디 갔지?"가 됩니다. 취소됨과 사유가 남아 있으면 바로 압니다
- **4장 샀는데 2장만 보이는 혼란**이 없습니다
- **초대권 담당자 화면과 동작이 같습니다.** 회수된 좌석이 회색 "회수됨"으로 남습니다 (`09` 참조)

**전부 취소된 예매도 카드는 남습니다.** 모든 줄이 회색이고 "지난 예매" 쪽으로 내려갑니다 (`13` 참조).

**카드에는 실 결제액만** 둡니다. 결제와 환불이 오간 자세한 내역은 결제·환불 내역에서 봅니다 (`08` 참조). 변경할 때마다 환불·결제 두 줄이 생기므로 카드에 다 적으면 금방 길어집니다.

좌석 변경을 여러 번 하면 취소된 줄이 쌓입니다. 소규모 서비스라 드물고, 문제가 되면 "취소된 티켓 N장"으로 접어 두면 됩니다.

> 처음에는 "남은 티켓만 보이고 취소는 결제·환불 내역에서만"이었으나, 관객이 직접 하지 않은 취소를 알아차릴 방법이 없어 바꿨습니다.

## QR에 무엇이 담기나

**QR 안에는 티켓의 QR 열쇠 하나만 들어갑니다.** 이름도 좌석도 날짜도 들어가지 않습니다.

**QR 열쇠**는 티켓이 직접 가진, 추측할 수 없는 값입니다. 공유 링크 주소도 이 열쇠로 만듭니다. 티켓 번호(`0091-2`)와는 다릅니다 — 티켓 번호는 화면에 보이는 이름표이고, 열쇠는 검표용입니다. **재발행하면 열쇠만 바뀌고 티켓은 그대로**입니다 (아래 "QR 재발행").

스캔하면 그 열쇠로 조회해서 좌석·회차·유효 여부를 화면에 띄웁니다. 검표원이 보는 정보는 **QR에서 나온 게 아니라 서버에서 온 것**입니다.

### 왜 QR에 정보를 담지 않는가

- **위조** — QR에 이름과 좌석을 넣으면 누구나 자기 이름으로 QR을 만들어냅니다. 종이에 "VIP 1열"이라고 써서 들고 오는 것과 다르지 않습니다
- **변경** — 좌석을 바꿔주거나 취소 처리를 해도 QR은 이미 관객 폰에 있습니다. 정보가 박혀 있으면 취소된 티켓이 멀쩡해 보입니다
- **입장 여부** — "이미 들어왔는가"는 QR 안에 존재할 수 없습니다

> **QR은 열쇠고, 데이터는 서버에 있습니다.** 검표는 "이 열쇠가 진짜인가, 이미 썼는가"를 묻는 행위입니다.

## 묶음권 티켓

**3일권 1장 = QR 1개**입니다. 그 QR이 3일 내내 쓰입니다.

티켓 한 장이 **회차 세 개를 가리킵니다.** 일반 티켓은 하나를 가리킬 뿐 구조가 같습니다 (`14` 참조).

```
티켓 #1 (3일권 · 5/3~5/5)
 5/3 ✓ 입장 완료    ← 입장 기록 있음
 5/4 — 미입장
 5/5 — 미입장
```

날짜마다 쪼개면 사람 10명에 QR 30개가 되어 담당자가 나눠주기 어렵습니다. **사람당 하나**가 맞습니다.

**날짜별 사용 여부는 입장 기록으로 셉니다.** 같은 날 두 번 찍으면 중복 경고가 뜨고, 날짜가 바뀌면 다시 유효해집니다.

**검표 화면에는 그 날의 회차가 표시**됩니다.

> **스탠딩A · 5/4 입장분**
> 3일권 (5/3~5/5) · 2일차
> 유효

시간대를 나눈 전시라면 회차까지 나옵니다.

> **스탠딩A · 5/4 14-16시 입장분**
> 3일권 (5/3~5/5) · 2일차
> 유효

### 출연자가 바뀐 날을 포기하면

관객이 그날만 포기할 수 있습니다 (`04` 참조). 티켓은 그 날짜의 회차를 **계속 가리키되 "포기" 표시**가 붙고, 그날 몫이 환불됩니다. 그날 QR을 찍으면 "환불받은 날짜입니다"로 막힙니다. 결제·환불 내역에 한 줄이 남습니다.

**회차를 빼지 않고 표시를 붙이는 이유** — 빼버리면 검표가 "환불받은 날짜"와 "처음부터 다른 날짜 표"를 구분할 수 없고, 예매 카드에 "5/4 포기"를 보여줄 근거도 사라집니다.

```
3일권 · 스탠딩A    [QR 보기] [공유]
 5/4 포기 · 29,833원 환불 + 배상 2,983원
```

### 주최자가 그중 하루를 취소하면

**티켓은 그대로 두고 그날 몫만 환불합니다** (`08` 참조). 티켓은 여전히 세 회차를 가리키고, 취소된 날에 찍으면 회차가 취소됐으므로 검표에서 거부됩니다. 따로 처리할 게 없습니다.

```
3일권 · 스탠딩A    [QR 보기] [공유]
 5/4 취소됨 · 46,500원 환불 + 배상 4,650원
```

## 티켓 표기

| 상황 | 표기 |
|---|---|
| 블록 1개 | **12열 7번** |
| 블록 여러 개 | **1층 12열 7번** |
| 수량형 | **스탠딩A · 0091-2** |

수량형은 자리가 없으므로 **예매번호(초대권은 초대권 번호) + 순번**을 붙입니다.

```
예매번호 ...0091 로 4매 예매
 ├─ 0091-1
 ├─ 0091-2
 ├─ 0091-3
 └─ 0091-4
```

| | |
|---|---|
| **유일성** | 예매번호가 유일하므로 **공짜로 따라옵니다.** 값을 뽑고 중복을 확인하는 작업이 없습니다 |
| **분모 없음** | `0091-2`는 영구히 그 티켓입니다. 2장 취소해도 번호가 바뀌지 않습니다 |
| **중복 없음** | 같은 행사를 두 번 예매하면 `0091-1`과 `0134-1`로 갈립니다 |
| **부모가 드러남** | 어느 예매의 몇 번째 장인지 보여, 문의할 때 관객과 주최자가 같은 걸 가리킵니다 |

**초대권도 같은 방식**입니다 — 초대권 번호 + 순번. `14`의 "티켓의 부모는 예매 건 또는 초대권"이 번호 체계에 그대로 나타납니다.

### 왜 "3/4"를 버렸나

**분모 하나가 문제였습니다.** 2장 취소하면 네 장이 아닌데 4라고 적혀 있고, 같은 행사를 두 번 예매하면 `3/4`가 두 개 생깁니다. 분모를 없애고 예매번호를 앞에 붙이면 둘 다 사라집니다.

> 랜덤 값을 뽑는 안도 검토했으나, 행사마다 중복 확인이 필요하고 번호에서 부모를 알 수 없어 **예매번호 방식이 모든 면에서 낫습니다.**

### 예매번호는 추측할 수 없어야 합니다

순차 번호면 `0091`에서 "지금까지 91건 팔렸다"를 추측할 수 있습니다. 판매 현황은 주최자만 보는 숫자인데 (`11` 참조) 번호로 새어나갑니다.

**예매번호 자체를 추측 불가능하게 발급**하면 티켓 번호까지 함께 해결됩니다. `03`의 행사 주소에 이미 같은 원칙을 적용했습니다.

### 누가 쓰나

관객이 일행에게 넉 장을 나눠줄 때 구분용이고, 문의할 때 관객과 주최자가 같은 표를 가리키는 데 씁니다. **검표에서는 쓰지 않습니다.** QR로 조회되고, 수동 검색은 이름과 전화번호로 합니다 (`10` 참조).

### 티켓 화면

```
      [QR]

   1층 12열 7번
   R석

○○밴드 단독공연
3월 14일 (금) 19:00
○○아트홀
```

**좌석이 주인공**입니다. 관객이 현장에서 자리를 찾는 용도라 가장 크게 두고, 공연 정보는 아래에 작게 둡니다.

## 일행에게 티켓 전달

4매를 한 사람이 들고 있으면 일행이 따로 못 들어옵니다.

**단체 초대권 링크 페이지와 같은 모양의 목록을 씁니다** (`09` 참조). 장소는 다릅니다 — 이 목록은 마이페이지 예매 카드 안에 있습니다.

```
R석 12열 7번   [QR 보기] [공유]
R석 12열 8번   [QR 보기] [공유]  ✓ 입장 완료
R석 12열 9번   [QR 보기] [공유]
R석 12열 10번  [QR 보기] [공유]

[차례로 넘기기]
```

- **공유** — 따로 오는 친구에게 링크 전송
- **넘기기 모드** — 다 같이 와서 연속 스캔할 때. **이미 찍힌 티켓에 체크 표시**
- **입장 완료 표시** — 누가 들어왔는지 확인

### 공유 링크

**로그인 없이 열립니다.** 친구에게 가입을 요구하면 현장에서 막힙니다. 어차피 QR을 캡처해 보내면 로그인도 필요 없으니 보안이 더 나빠지지도 않습니다.

**링크 주소는 추측할 수 없어야 합니다.**

**소유권이 넘어가지는 않습니다.** 링크를 받은 사람은 그 티켓의 QR만 볼 수 있고, 취소와 변경은 산 사람만 합니다.

**받은 사람의 예매 내역에는 나오지 않습니다.** 받은 사람이 가입해 있어도 마찬가지입니다. **예매 내역에는 내가 돈을 내고 산 표만** 나오고, 링크로 받은 표는 그 링크 페이지에서만 봅니다. 초대권도 같습니다 (`09` 참조).

> 가입한 사람이 링크를 열면 예매 내역에 담아주는 안도 생각할 수 있지만, 그러면 **같은 표 한 장이 두 계정에 보입니다.** 4장을 산 사람의 계정과 1장을 공유받은 친구의 계정 양쪽에요. 누구 표인지가 흐려집니다.

### 공유 링크의 수명

링크는 **티켓에 붙어 있습니다.** 티켓이 사라지면 링크도 사라집니다.

| 경우 | 처리 |
|---|---|
| 그 티켓이 취소됨 | 즉시 무효 |
| **변경** | 기존 티켓이 취소되므로 무효. 새 티켓에 새 링크 (`08` 참조) |
| **QR 재발행** | 즉시 무효 |
| 행사가 끝남 | 자동 만료 |

**무효가 된 링크를 열면 이유를 알려줍니다.** 빈 화면이나 오류를 띄우면 받은 사람이 링크가 잘못된 줄 압니다.

> ❌ 취소된 티켓입니다
> 예매하신 분께 확인해 주세요.

| 무효가 된 이유 | 링크 화면 |
|---|---|
| 티켓 취소 · 변경 | "취소된 티켓입니다" · 예매하신 분께 확인해 주세요 |
| QR 재발행 | "재발행으로 바뀐 티켓입니다" · 예매하신 분께 새 링크를 받아 주세요 |
| 행사 종료 | "종료된 행사입니다" |

## QR 재발행

### 왜 필요한가

**분실은 사실상 안 생깁니다.** 로그인하면 마이페이지에 항상 있으니까요.

실제로 필요한 건 **유출**입니다.

> 친구에게 QR을 보냈는데 그 친구가 못 오게 됐습니다.
> 캡처가 그 친구 폰에 남아 있고 단톡방에도 올라갔을 수 있습니다.
> **내가 가진 QR과 똑같은 게 밖에 돌아다닙니다.**

먼저 찍는 사람이 들어가니, 내가 늦게 가면 못 들어갈 수 있습니다. 재발행하면 밖에 돌아다니는 QR이 전부 무효가 됩니다.

### 신청은 관객, 처리는 관리자

**관객이 직접 재발행할 수 없습니다.** 실수나 장난으로 일행 QR을 무효화할 수 있기 때문입니다.

> **QR 재발행 신청**
> 사유: ○ 티켓이 외부에 유출됨
> ○ 계정이 도용된 것 같음
> ○ 기타 (직접 입력)
>
> ※ 재발행하면 **기존 QR과 공유 링크가 모두 무효**가 됩니다. 일행에게 공유한 티켓이 있다면 다시 보내주세요.

마지막 줄이 중요합니다. 재발행하고 나서 "친구가 못 들어갔다"는 민원이 안 나오게요.

### 처리

| | |
|---|---|
| 신청 | 관객 (사유 선택) |
| 처리 | **관리자** |
| 효과 | **QR 열쇠를 새로 바꿈** → 기존 QR·공유 링크 즉시 무효, 새 QR 발급. 티켓은 그대로 |
| 반려 | 관리자가 사유를 적어 반려할 수 있음 |
| 통지 | 완료·반려 모두 관객에게. 완료 안내에 **"저장해 둔 QR 캡처도 새로 저장하세요"** |
| 기록 | 재발행 이력 남김. **옛 열쇠도 이력에 보관** |

**옛 열쇠를 보관하는 이유** — 우리는 관객에게 QR을 미리 캡처해 두라고 안내합니다 (`10` 참조). 재발행 뒤 관객이 옛 캡처를 내밀 수 있습니다. 옛 열쇠를 모르면 검표 화면이 "확인할 수 없는 QR"을 띄워 위조처럼 보입니다. 알면 이렇게 띄웁니다.

> ⚠️ 재발행으로 바뀐 QR입니다
> 관객 폰에서 새 QR을 열거나 수동 검색하세요

**관리자 처리 목록에서 공연이 임박한 신청을 눈에 띄게 표시**합니다. 며칠씩 방치되면 공연 당일이 됩니다.

### 왜 주최자가 아니라 관리자인가

- 사유 중 "계정이 도용된 것 같음"은 **플랫폼 보안 문제**라 주최자가 판단할 일이 아닙니다
- 주최자에게 맡기면 주최자마다 처리 기준과 속도가 달라집니다
- 빈도가 아주 낮습니다. 행사당 한두 건이나 될까요. 관리자 부담이 작습니다

> 처음에는 "주최자 또는 관리자"였으나, 계정 보안 판단을 주최자에게 맡길 수 없어 관리자로 모았습니다.

### 처리가 늦어도 표 주인은 들어갑니다

공연은 주로 저녁과 주말이라 관리자가 바로 처리하지 못할 수 있습니다. 그래도 현장 대비책이 있습니다.

> 유출된 QR로 누군가 먼저 들어갔습니다.
> 진짜 주인이 QR을 찍으면 **"이미 입장 처리된 티켓"** 경고가 뜹니다 (`10` 참조).
> 스태프가 관객이 말한 이름과 연락처로 수동 검색해 **같은 표가 나오면** **[그래도 입장 처리]** 를 누릅니다. 화면에는 이름이 아니라 표 정보만 나옵니다 (`10` 참조).

재발행은 유출을 **미리** 막는 수단이고, 늦어도 현장에서 수습됩니다.

## 행사가 끝나면

| | |
|---|---|
| QR | **무효, 버튼 자체를 안 그림** |
| 공유 링크 | 만료 |
| **티켓** (좌석 · 금액 · 취소 여부) | **5년 보존**, 이후 누가 샀는지만 지움 (`11` 참조) |
| 입장 기록 | 30일 후 통째로 삭제 (`10` 참조) |
| 집계 숫자 | 영구 보존 |

### 티켓은 지우지 않습니다

**법정 보존 대상입니다.** 전자상거래법 시행령 제6조가 "대금결제 및 재화등의 공급" 기록을 5년간 남기라고 합니다 (`11` 참조).

**티켓이 바로 그 "공급" 기록입니다.** 예매 건에는 "165,000원 결제"만 있고, 무엇을 공급했는지(12열 7번을 5만원에)는 티켓에 있습니다.

**5년이 지나도 티켓은 지우지 않고, 누가 샀는지만 지웁니다** (`11` 참조). 주최자의 판매 현황과 통계가 그대로 남아야 하기 때문입니다.

**용량도 문제가 되지 않습니다.** 행사 500개 × 300장 × 5년이면 75만 행, 인덱스 포함 300MB 안팎입니다. 오히려 지우는 쪽이 비쌉니다 — 티켓이 없으면 예매 내역을 그릴 요약 저장소를 또 만들어야 하고, 분쟁 시 복구가 불가능합니다.

### 화면에서는 버튼만 빠집니다

```
예매 내역 → 예매 카드 → 티켓 목록
                          ├─ 아직 볼 공연이 남은 표   [QR 보기] [공유]
                          └─ 공연이 끝난 표            버튼 없음. 좌석 · 금액만
```

**티켓이 가리키는 회차가 모두 끝났으면 버튼을 안 그립니다.** 판단은 티켓마다입니다. 8회차 행사에서 3/14 표는 3/14 공연이 끝나면 버튼이 사라지고, 3일권은 마지막 날이 끝나야 사라집니다. 티켓은 그대로 있고 화면만 달라집니다.

관객 화면에는 **"공연 종료"** 표시와 함께 좌석·금액이 보입니다.

## 티켓 양도는 만들지 않습니다

### 이미 사실상 가능합니다

QR 화면을 캡처해서 보내면 끝입니다. 검표는 QR 열쇠만 보고 이름을 대조하지 않으니 누가 들고 와도 통과됩니다.

그러니 질문은 "양도를 허용할까"가 아니라 "공식 기능으로 만들까"였고, **만들지 않기로** 했습니다. 소규모 행사에서 모르는 사람 간 거래는 드물고, 공식 기능은 암표 거래를 쉽게 만듭니다.

### 대신 명시합니다

> 티켓 양도 기능은 제공하지 않습니다. QR을 공유할 경우 **먼저 스캔한 사람이 입장**하며, 이로 인한 문제는 책임지지 않습니다.

이 문구가 없으면 현장에서 "쟤가 먼저 들어갔다"는 분쟁이 생겼을 때 설명할 근거가 없습니다.
