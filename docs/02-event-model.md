# 02. 날짜 · 회차 · 구역 · 블록 · 좌석

**이 문서가 가장 중요합니다.** 여기 정의한 모델이 가격, 예매, 초대권, 검표에 전부 걸려 있습니다.

전체 관계도는 `14`에 있습니다.

## 두 개의 축

```
【도면】 극장이 어떻게 생겼는가       ← 행사에 하나
  블록 ─ 좌석        좌석 번호
  구역               가격

【재고】 언제 몇 자리가 남았는가
  행사 → 날짜 → 회차  ← 재고는 회차에만 붙음
```

**도면과 재고는 다른 층입니다.**

| | 어디에 붙나 | 예 |
|---|---|---|
| **도면** | **행사** | "1층 12열 7번은 R석, 5만원" |
| **재고** | **회차 × 좌석** | "3/14 19시의 12열 7번은 팔림" |

좌석은 하나, 판매 상태는 회차마다입니다. 같은 "1층 12열 7번"이 3/14에는 팔렸고 3/15에는 비어 있을 수 있습니다.

**도면은 행사에 하나뿐이고 회차마다 다를 수 없습니다.**

> 8회차 공연에 도면이 8개 생기면 구역 기본가도 8벌이 되어, "기본가는 하나, 회차에는 조정값만"(`05`)이 성립하지 않습니다.
>
> 같은 극장에서 같은 작품을 올리므로 실제로 달라지는 경우가 거의 없습니다. 연극제처럼 회차마다 작품이 바뀌어도 극장 좌석은 그대로입니다. **정말 다르면 행사를 따로 만듭니다.**

## 도면은 행사마다 따로 갖습니다

**다른 행사와 도면을 같이 쓰지 않습니다.** 행사를 복제하면 도면이 **통째로 복사**되고, 그 뒤로 원본과 복사본은 아무 관계가 없습니다 (`04` 참조).

> 주최자가 작년 공연을 복제해 올해 공연을 만들고, 올해 도면에서 "1층"을 "지하 1층"으로 바꾸고 12열을 없앴습니다.
> **작년 예매자의 내역에는 여전히 "1층 12열 7번"이 보여야 합니다.**

여러 행사가 주최자의 도면 하나를 같이 쓰면, 올해 고치는 순간 **작년 예매 내역이 바뀌거나 좌석이 사라집니다.** 막으려면 도면에 버전을 붙여야 하고 복잡도가 크게 오릅니다.

따로 가지면 비슷한 도면이 행사 수만큼 쌓이지만, 도면 하나는 좌석 수백 개라 양이 미미하고 **지난 행사가 절대 바뀌지 않는다는 보장**을 얻습니다.

**행사가 끝나면 도면은 고정됩니다** (`04` 참조). 그래서 티켓이 좌석을 가리키기만 해도 1년 뒤에 같은 번호가 나옵니다 (`07` 참조).

**도면을 통째로 바꾸는 경우는 하나뿐입니다** — 첫 회차가 시작되기 전에 **좌석 배치가 다른 곳으로 장소를 옮길 때**입니다. 관리자 승인을 거치고, 좌석이 있는 티켓(예매·초대권)은 재배정 규칙(구역 유지, 일행은 붙여서, 원래 앞자리 순서대로)에 따라 새 도면으로 옮겨집니다 (`04` 참조). 공연이 하나라도 열린 뒤에는 바꿀 수 없습니다. 지난 회차 표의 좌석 번호가 바뀌기 때문입니다.

## 구역과 블록은 다른 축입니다

| | 역할 | 예 |
|---|---|---|
| **구역** | 가격 | VIP석, R석, 스탠딩A |
| **블록** | 좌석 번호 | 1층, 2층, 좌측 |

한 구역이 여러 블록에 걸칠 수 있고(R석이 1층과 2층에), 한 블록에 여러 구역이 섞일 수도 있습니다(1층에 VIP와 R석이).

# 날짜와 회차

```
행사
 └─ 날짜
     └─ 회차            ← 재고가 붙는 유일한 곳
```

**날짜가 회차보다 위에 있습니다.** 날짜를 가리켜야 하는 것이 셋이기 때문입니다.

| | 무엇을 가리키나 |
|---|---|
| 1인 총 매수 "날짜별" (`06`) | 날짜마다 4매 |
| 운영 시간 | 날짜마다 다름 — 주말은 늦게까지 |
| 묶음권 (`05`) | 날짜를 건너 묶음 |

## 회차형과 종일형 — 회차 방식

가장 먼저 갈리는 구분이고, 문서에서는 **회차 방식**이라 부릅니다. 공연·전시·페스티벌을 고르는 **유형**과는 다른 축입니다 (`03` 참조). 회차형 전시도, 종일형 페스티벌도 있습니다.

**기준은 내용이 같냐 다르냐가 아닙니다.**

> **재고가 시간 단위로 나뉘는가**

그리고 이것은 **날짜 아래 회차가 몇 개냐**로 나타납니다.

```
공연       3/14 ─ 15:00 회차 · 19:00 회차
전시       3/14 ─ 10:00~18:00 회차 하나
혼잡 전시   3/14 ─ 10-12시 · 12-14시 · 14-16시
페스티벌    5/3 ─ 종일 회차 하나
```

| | **회차형** | **종일형** |
|---|---|---|
| 날짜 아래 회차 | 여러 개 | **하나** |
| 예 | 공연, 시간대를 나눈 전시 | 전시, 페스티벌 |
| 관객이 고르는 것 | 언제 들어갈지 | 며칠 갈지 |

연극제는 회차마다 다른 작품을 올리지만 **각 회차마다 좌석 재고가 따로 있으므로 회차형**입니다. 페스티벌은 들어가면 그 날 내내 돌아다니므로 재고가 날짜 단위로만 존재합니다.

### 시간을 쪼개려면 회차형으로 등록합니다

혼잡한 전시를 시간대로 나눠 인원을 분산시키고 싶다면 **회차형 전시**입니다. 10-12시, 12-14시 회차를 만들고 회차별 정원을 설정합니다.

> 이전 문서에는 "종일형 시간대 분할"이 있었습니다. 종일형의 정의가 "재고가 시간으로 나뉘지 않는 것"인데 시간으로 나누는 기능을 달아둔 **문서 내 모순**이었습니다. 삭제했습니다.

**주의: 회차는 "입장 가능한 창구"이지 "퇴장 시각"이 아닙니다.** 14-16시 티켓으로 15시 50분에 들어가서 18시까지 봐도 됩니다. 안내 문구를 이렇게 써야 합니다.

## 회차의 시간 정보

**회차형과 종일형이 같은 모양을 가집니다.**

```
회차형 (공연)    3/14 · 19:00 시작 ~ 21:00 종료
종일형 (전시)    3/14 · 10:00 오픈 ~ 18:00 마감
```

| | 필수 | 선택 |
|---|---|---|
| 회차형 | 시작 시각 | 종료 시각 (러닝타임) |
| 종일형 | 운영 시작~종료 | 마지막 입장 시각 |

**종일형 마지막 입장**은 비워두면 운영 종료 시각과 같게 처리합니다.

**종료 시각은 행사 종료 판정에 쓰입니다** (`04` 참조). 비워둔 채로 두면 "언제 끝났나"를 알 수 없으므로, **그 회차의 시간 수정이 잠기는 시점(회차 시작 1주일 전)에 입력을 요구**합니다.

**공연 중단 판정에도 쓰입니다.** 예정 공연 시간의 절반 이하만 하고 멈췄는지를 시작~종료 시각으로 봅니다 (`08` 참조).

### 출연 (선택)

더블 캐스팅 공연은 **회차마다 누가 나오는지**가 관객이 회차를 고르는 기준입니다 (`15` 한서윤). 그래서 회차에 **출연** 칸을 둡니다.

| | |
|---|---|
| 입력 | 선택. 자유 입력 한 줄 ("김배우 · 박배우") |
| 관객 화면 | 행사 상세의 회차 목록, 회차 선택 화면 — 회차 시간 아래 한 줄 |
| 변경 이력 | **제목·소개·포스터와 같이 남김.** 무엇을 보고 샀는지의 근거 (`03` 참조) |
| 티켓이 있는 회차에서 바꾸면 | "예매자에게 알릴까요?" 창 (`04` 참조) |
| 출연자 변경 알림을 보내면 | 그 회차 출연 칸도 알림 내용대로 바뀜 (`04` 참조) |

**출연 칸을 고치는 것만으로는 출연자 변경 알림이 되지 않습니다.** 소개 글을 고치는 것과 같습니다. 주요 출연자가 바뀌었으면 [출연자 변경 알림]을 따로 보내야 이미 산 관객에게 권리가 생깁니다 (`04` 참조).

### 날짜마다 운영 시간이 다를 수 있습니다

전시가 주말에 더 늦게까지 여는 경우가 흔합니다. 30일짜리 전시에 30번 입력하게 하면 안 되므로, **행사 단위로 기본 운영 시간을 한 번 넣고 다른 날만 덮어쓰는** 방식입니다.

# 구역

> **구역 = 가격이 붙는 재고 묶음**

- **지정형** — 구역 안에 좌석이 하나하나 있음. 관객이 자리를 고름
- **수량형** — 구역 안에 정원 숫자만 있음. 관객은 매수만 고름

| | 구역 구성 | 예시 |
|---|---|---|
| 공연 | 지정형 여러 개 | VIP석 40 / R석 120 / S석 80 |
| 페스티벌 | 수량형 여러 개 | 스탠딩A 300 / 스탠딩B 500 / 테이블석 50 |
| 전시 | 수량형 하나 | 전체 200 |

**한 행사 안에서 섞을 수 있습니다.** 공연에 "1층 스탠딩 + 2층 좌석"이 있어도 되고, 페스티벌에 테이블석만 지정형으로 둘 수도 있습니다.

**묶음권은 수량형 구역에서만** 팝니다 (`05` 참조).

## 왜 이렇게 묶었나

처음에는 공연의 "좌석 등급", 페스티벌의 "구역", 전시의 "정원"을 각각 다르게 다루려 했습니다. 그러면 서비스가 사실상 세 개가 됩니다.

셋 다 **"언제 갈지 고르고 → 무엇을 받을지 고르고 → 결제한다"** 로 같습니다.

## 설정 흐름

```
구역 추가
 ├─ 지정형 → 블록 배치 → 좌석 생성 → 구역 배정
 └─ 수량형 → 정원 입력만
```

**수량형 구역에는 블록도 좌석도 없습니다.** 번호를 매길 대상이 없으니까요. 스탠딩 구역이 여러 개면 **구역 이름**으로 나눕니다("스탠딩A", "스탠딩B").

수량형 티켓은 자리가 없으므로 **예매번호 + 순번**으로 구분합니다 — `0091-2` (`07` 참조).

# 블록

좌석 번호를 유일하게 만드는 단위입니다. 블록이 둘인데 이름이 없으면 양쪽에 "1열 7번"이 생겨 구분이 안 됩니다.

**이름은 자유 입력**입니다.

> 블록 이름
> `1층`
> *예: 1층, 2층, 좌측, 중앙 · 구역 이름(R석, S석)과 겹칠 수 없습니다*

**중복 검증**을 겁니다. 같은 이름의 블록 두 개를 못 만들고, 구역 이름과도 겹칠 수 없습니다.

> ⚠️ "R석"은 이미 구역 이름으로 쓰고 있습니다. 다른 이름을 입력해 주세요.

**비워두면 "블록 1", "블록 2"로 자동 부여**됩니다. 블록이 하나뿐인 소극장은 표시도 생략되므로 신경 쓸 필요가 없습니다.

> 처음에는 A~Z 고정 식별자에 표시 이름을 따로 받는 안이었으나, **주최자가 두 군데를 입력하게 되어** 이름 하나로 통합했습니다. 중복은 검증으로 막습니다.

## 판매 중에도 블록 이름을 고칠 수 있습니다

> "1층"을 "1증"으로 잘못 쓴 채 판매를 시작했고, 이미 30장이 팔렸습니다.

**고칠 수 있습니다.** 이미 팔린 30장의 표기도 같이 "1층"으로 바뀝니다. 블록 이름은 블록 한 곳에만 있고 티켓은 좌석을 가리키기만 하므로, **티켓을 하나하나 고치지 않습니다** (`07` 참조).

**팔린 좌석이 있는 블록의 이름을 바꾸면 "예매자에게 알릴까요?" 창**을 띄웁니다. 알릴지는 주최자가 고릅니다 (`04` 참조). **알렸는지는 기록하지 않습니다** — 아래처럼 이력 자체를 남기지 않기 때문입니다.

**변경 이력은 남기지 않습니다.** 관객은 좌석을 고를 때 번호를 보지 않으므로 (아래 참조) 블록 이름을 "보고 샀다"는 다툼이 생길 수 없습니다. 제목·소개·포스터와 다른 점입니다 (`03` 참조).

관객이 캡처해 둔 QR 이미지에는 옛 이름이 찍혀 있겠지만, QR에는 QR 열쇠만 들어 있어 검표에는 문제가 없습니다 (`07` 참조). 검표 화면은 서버에서 새 이름을 읽습니다.

## 좌석 번호 표기

| 상황 | 표기 |
|---|---|
| 블록 1개 | **12열 7번** |
| 블록 여러 개 | **1층 12열 7번** |

**블록이 하나면 생략**합니다. "블록 1 12열 7번"은 정보가 없습니다.

# 좌석 배치도 (지정형 구역)

## 템플릿 우선

규모 기준 카탈로그 4~5개를 제공합니다.

- 소극장형 100석 / 블랙박스형 150석 / 강당형 300석 / 대학 소공연장 500석 / 빈 캔버스

**템플릿이 많으면 고르는 것 자체가 일이 됩니다.** 어차피 수정할 거라 정확히 맞출 필요가 없습니다.

## 에디터는 블록 단위

픽셀 단위 자유 배치가 아닙니다.

- 블록 추가 = 이름 + "5행 × 10열" 덩어리 얹기
- 블록 위치 이동, 각도 조절 (부채꼴 객석용)
- 블록 안 개별 좌석 비활성화
- **좌석을 구역에 배정** (색칠)
- 좌석 속성 지정
- 무대 위치 지정

**200석짜리 소극장이 5분 안에 만들어져야 합니다.**

## 에디터와 선택 화면은 다른 화면입니다

같은 도면을 쓰지만 화면은 둘입니다.

| | **배치도 에디터** | **좌석 선택 화면** |
|---|---|---|
| 누가 | 주최자 | 관객 |
| 뭘 하나 | 배치도를 **만든다** | 자리를 **고른다** |
| 기기 | 데스크톱 우선 | **모바일 필수** |

**모바일 에디터**는 템플릿 선택·블록 추가·구역 배정까지는 편하게, 개별 좌석 토글 같은 정밀 작업은 줌인이 필요하다고 안내합니다.

## 관객에게는 번호를 보여주지 않습니다

좌석을 고르는 동안에는 **구역 색과 가격만** 보입니다.

```
R석 50,000원        ← 색으로 구분
선택한 좌석 2석
```

고르는 중에 "12열 7번"을 읽을 필요가 없습니다. **번호는 예매 완료 후 티켓에 표시**됩니다 (`07` 참조).

# 좌석 속성

성격이 둘로 갈립니다. **어디에 붙는지가 다릅니다.**

| 속성 | 붙는 곳 | 배치도 | 관객 화면 |
|---|---|---|---|
| 일반 | 도면 | 기본 | — |
| **휠체어** | **도면** | 아이콘 + 색 구분 | "휠체어 이용자용 좌석입니다" + **확인 체크** |
| **시야제한** | **도면** | 색 구분 | "무대 일부가 보이지 않을 수 있습니다" + **동의 필수** |
| **판매 제외** | **회차** | 회색 | 선택 불가 (`09` 참조) |

휠체어와 시야제한은 **물리적 사실**이라 바뀌지 않습니다. 판매 제외는 **운영 판단**이라 회차마다 다릅니다.

## 판매 제외는 회차 단위입니다

첫 회차만 기자를 부르는 건 정상입니다. 도면 단위면 8회차 전부 빠집니다. 초대권도 회차 단위로 발권되므로 발권 단위와 맞습니다.

**"전 회차 일괄 적용" 버튼이 반드시 필요합니다.** 전 회차 같은 자리를 빼는 게 대부분인데, 없으면 8번 반복합니다.

**수량형 구역에서는 "관계자용 10석 확보"** 로 처리합니다 (`09` 참조).

## 시야제한석 동의가 중요합니다

**없으면 환불 분쟁이 생깁니다.** "무대가 안 보였다"며 환불을 요구하는데, 고지했다는 근거가 없으면 설명할 수 없습니다.

> ☐ 이 좌석은 무대 일부가 보이지 않을 수 있음을 확인했습니다.

가격은 주최자가 정합니다. 보통 낮게 매기는데, 구역을 따로 만들어 가격을 다르게 하면 됩니다.

## 휠체어석은 체크박스 확인

**본인확인을 하지 않으니 검증할 방법이 없습니다.** "휠체어 이용자 또는 동반인입니다" 확인을 받는 선에서 그칩니다. **실제 검증은 현장에서** 이루어집니다. 휠체어석은 공간 구조가 달라 일반 관객이 앉으면 바로 드러납니다.

**동반석**은 별도로 정의하지 않습니다. 주최자가 휠체어석 옆에 일반석을 배치해두면 관객이 알아서 함께 고릅니다.

**수량형 구역에서는 별도 구역으로** 만듭니다. "휠체어 구역 4석" 같은 식으로요.

# 입구 (게이트)

주최자가 입구 목록을 미리 등록합니다. "정문", "2층 전용", "VIP 입구" 같은 식. **도면에 속합니다** — 회차마다 달라지지 않습니다.

검표 시작 시 고를 대상이 되고, **게이트별 입장 현황**이 통계로 나옵니다 (`11` 참조).
