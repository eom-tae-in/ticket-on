# 11. 주최 관리 · 정산 · 데이터 보관

승인된 주최자의 운영진(소유자·운영자)에게만 열리는 공간입니다. 마이페이지와 분리되어 있습니다 (`01` 참조).

## 구조

```
주최 관리
 ├─ 주최자 전환  ※ 여러 곳에 소속된 경우
 ├─ 내 행사 목록
 │   ├─ 작성 중 (진행률 · 이어서 작성)
 │   └─ 판매 대기 / 판매 중 / 판매 종료 / 행사 종료
 │       └─ 행사 상세
 │           ├─ 설정 편집 (위저드)
 │           ├─ 관계자석 · 초대권 (직접 알려야 할 초대권 포함)
 │           ├─ 검표 계정
 │           ├─ 예매 현황
 │           ├─ 입장 현황
 │           ├─ 정산
 │           ├─ 판매 중단·재개 / 연기 신청 / 장소 변경 신청
 │           ├─ 출연자 변경 알림 · 공연 지연 처리 · 공연 중단 처리 (소유자만)
 │           ├─ 회차 취소 · 행사 취소 (소유자만)
 │           └─ 행사 삭제 (팔린 표·초대권이 없었을 때만. 판매 시작 후는 소유자만)
 ├─ 운영진 관리  ※ 초대·내보내기·소유자 넘기기는 소유자만
 ├─ 내 프로필 (닉네임 · 한 줄 소개)
 ├─ 주최자 공개 정보 (소개 · SNS 링크 · 로고) — 운영진 누구나
 └─ 주최자 정보 · 사업자 정보 · 정산 계좌 (소유자만) — 주최자명 변경은 소유자가 바로, 이력·알림 남음. 사업자 정보·계좌 변경은 관리자 확인 뒤
```

**과거 행사 이력이 한 주최자에 남는 것**이 이 구조의 핵심 이점입니다. 대표가 바뀌어도 이력이 그대로 이어집니다. 승인 심사와 신뢰도 판단의 근거가 됩니다.

## 예매 현황

- 회차별 판매 수량과 잔여
- **오늘 판매 수** — 공연 기간에 폰으로 "오늘 몇 장 팔렸지"를 보는 숫자 (`15` 박정훈). 폰에서는 숫자 카드와 회차 목록으로 보여줍니다
- 구역별 판매 현황
- **판매와 초대를 분리 집계** (`09` 참조)
- 조기예매 소진 현황, 쿠폰 사용 현황
- 오픈 전이면 **알림 신청 수** (관심도 지표)

**결제 대기 건은 표시하지 않습니다** (`06` 참조).

## 입장 현황

행사 당일에 보는 화면입니다.

- **입장률** — 예매 312명 중 입장 287명 · **92%**
- **게이트별 분포** — 어느 입구가 막히는지
- **시간대별 입장 추이**
- 강제 통과 처리된 건 목록 (`10` 참조)
- **티켓 없이 입장한 인원** — 시각·입구·인원·사유·처리한 운영진 (`10` 참조)

목록에는 **시각 · 입구 · 좌석**만 나옵니다. 누가 산 표인지는 나오지 않습니다.

**검표 계정에서는 이 정보가 보이지 않습니다.**

입장률은 **다음 행사를 준비할 때** 쓰입니다. 노쇼율이 10%면 그만큼 더 팔아도 되고, 입장 추이를 보면 다음에 언제 문을 열지 판단합니다.

## 정산

### 두 가지를 나눕니다

- **판매 집계** — 테스트 결제여도 실제로 유용합니다. 주최자가 매일 봅니다
- **정산(송금)** — 테스트라 실제로는 일어나지 않습니다

**판매 집계는 제대로, 정산은 화면 흐름만** 만듭니다.

### 판매 집계

| 항목 | |
|---|---|
| 총 판매액 | 회차별·구역별 |
| 환불액 | 취소 수수료 차감분 포함 |
| 순매출 | 판매 − 환불 |
| 배상액 | 회차·행사 취소, 공연 중단, 출연자 변경으로 나간 10% (`08` 참조) |
| 지연 환급액 | 30분 이상 지연으로 돌려준 10% (`08` 참조) |
| 판매 수량 | 초대권과 분리 |

### 정산 내역

| 항목 | |
|---|---|
| 정산 대상 기간 | |
| 정산 예정액 | **순매출 − 배상액 − 지연 환급액 − 수수료 − 이전 미수금** |
| 상태 | 정산 대기 / 정산 완료 |
| 정산일 | |

**수수료는 0원**입니다. 예매 수수료를 받지 않기로 했고 PG 수수료도 테스트라 발생하지 않습니다. 계산 자리는 만들어두되 값은 0입니다.

**정산 완료 처리는 관리자가 수동으로** 누릅니다.

**배상과 지연 환급은 주최자 부담이므로 정산에서 뺍니다.** 관객에게는 우리가 먼저 돌려주고, 주최자 몫에서 차감합니다.

> 회차 하나를 취소해 배상금이 나갔습니다. 정산 화면에서 그 돈이 빠져 있는지 궁금합니다 (`15` 박정훈).
> → 정산 내역에 "배상 −36,000원" 줄이 따로 보입니다.

### 정산 시점은 행사 종료 후 영업일 7일 이내

편의 문제가 아니라 구조적인 이유가 있습니다.

> 행사 전에 정산하면, 이후 환불이 나갈 때 돌려줄 돈이 없습니다.

공연 3일 전에 취소하면 80%를 환불해야 하는데 이미 송금했으면 회수해야 합니다. 그래서 **환불 가능 기간이 끝난 뒤**, 즉 행사가 끝난 뒤에 정산합니다.

**주최자가 궁금해할 것**에 답이 화면에 있어야 합니다.

> 정산 예정일: 3월 20일 (행사 종료 후 영업일 7일 이내)
> 환불 가능 기간이 끝난 뒤 정산됩니다.

이 한 줄이 없으면 문의가 계속 옵니다.

**취소된 행사도 정산합니다.** 취소된 뒤에는 더 나갈 환불이 없으므로 **취소 시점부터** 영업일 7일 이내입니다. 환불과 배상으로 대개 마이너스가 됩니다 (아래, `04` 참조).

**불가항력 배상 확인이 끝나지 않은 행사는 정산 완료를 누를 수 없습니다.** 배상을 낼지 말지가 정산액을 바꾸기 때문입니다 (`04` 참조).

### 정산액이 마이너스인 경우

전액 환불된 행사는 환불이 판매를 넘습니다.

**주최자에게 청구**하고 우리가 관객에게 돌려줍니다. 관객은 주최자가 아니라 **우리를 믿고** 결제했으니 환불이 먼저입니다.

미납은 **주최자에 미수금으로 기록**하고 다음 행사 정산에서 차감합니다.

| | |
|---|---|
| 주최자 화면 | 정산 화면 맨 위에 **"미수금 N원"** |
| 알림 | 정산 완료 메일에 미수금 표시 (`12` 참조) |
| 다음 정산 | **자동으로 차감** |
| 직접 납부 | 관리자가 **납부 확인** 처리 |
| 주최자 닫기 | **미수금이 있으면 닫을 수 없음** (`01` 참조) |
| 오래 안 내면 | 관리자가 **정지 1단계**(신규 개설 차단)를 걸 수 있음 (`01` 참조) |

테스트 결제라 실제로는 일어나지 않지만 화면 흐름은 있어야 합니다.

### 정산 계좌 변경

**소유자만 바꿀 수 있고, 관리자가 확인한 뒤 적용됩니다.**

> 운영자로 들어온 사람이 소유자 자리를 넘겨받고 계좌를 자기 것으로 바꾸면 정산금이 그 사람에게 갑니다 (`01` 참조).

정산은 원래 관리자가 손으로 처리하므로(위 "정산 완료 처리") 확인 절차가 크게 늘지 않습니다. 확인 중에는 기존 계좌가 그대로 쓰입니다.

**정산이 끝난 건의 계좌는 바꿀 수 없습니다.** 이미 보낸 돈이니까요.

### 만들지 않는 것

자동 송금 연동, 세금계산서·현금영수증, 정산 주기 자동화, PG 수수료 정밀 계산.

## 통계 — 연령대

```
예매자 연령대 (예매자 214명 기준)

10대 4% · 20대 38% · 30대 31% · 40대 18% · 50대 이상 9%

※ 예매한 분이 직접 입력한 생년월일 기준입니다.
  함께 온 일행과 초대권은 포함되지 않습니다.
※ 예매자가 30명 미만이면 표시하지 않습니다.
```

| 규칙 | |
|---|---|
| 세는 단위 | **예매한 사람(계정)** — 4장을 산 사람은 1명 |
| 표시 조건 | **예매자 30명 이상**일 때만 |
| 범위 | 행사 전체와 회차별을 **각각** 30명 기준으로 |
| 형태 | **비율만.** 개별 인원수는 표시하지 않음 |

**30명 기준을 두는 이유** — 예매자가 적으면 "50대 1명"만 보고도 누군지 짐작할 수 있습니다. 소극장 공연은 회차별로는 30명이 안 되는 경우가 많아 대부분 숨겨지지만, 행사 전체로 합치면 보입니다.

**함께 온 일행은 셀 수 없습니다.** 계정이 없어 나이를 모릅니다. "온 사람 전체"가 아니라 "예매한 사람" 기준이라는 걸 화면에 꼭 적습니다.

**성별 통계는 없습니다.** 성별을 받지 않습니다 (`01` 참조).

**정확도 한계** — 생년월일은 본인이 직접 입력한 값이라 검증되지 않습니다 (`01` 참조). 화면의 안내 문구가 이 점을 밝힙니다.

## 데이터 보관

| 데이터 | 처리 |
|---|---|
| 예매 건·티켓·결제 기록 | **법정 기간 보존.** 티켓이 "재화의 공급" 기록 (`07` 참조) |
| 계정 정보 | 회원이 유지하는 동안 |
| 제목·소개·포스터 변경 이력 | **행사 종료 후 6개월** (표시·광고 기록, `03` 참조) |
| 입장 기록 · 티켓 없는 입장 기록 | **행사 종료 30일 후 통째로 삭제.** 집계 숫자만 남김 (`10` 참조) |
| 장소 변경 재배정표 | 티켓과 같이 보존 (`04` 참조) |
| 부가 기록 (알림 발송 이력, 접속 기록) | **90일 후 파기** |
| 집계 통계 | 유지 |
| 닫힌 주최자 | **지우지 않음.** "닫힘" 상태로 이력 전부 보존. 다시 열면 이어짐 (`01` 참조) |
| 운영진 소속 이력 | 유지 — 프로필의 "참여한 주최자"와 관리자 판단에 쓰임 |
| 도면 — 좌석 배치도·블록·구역·입구 | **행사와 함께 유지.** 행사마다 따로 갖고 복제로 재사용 (`02` 참조) |
| 회원 탈퇴 시 | 법정 보존 대상 외 즉시 파기 |
| **법정 보존 기간이 지난 예매·티켓·결제 기록** | **관객 개인을 알아볼 수 있는 정보 삭제.** 집계는 남김 |

### 법정 보존 기간

전자상거래법 시행령 제6조 제1항:

| 기록 | 기간 |
|---|---|
| 표시·광고 | **6개월** |
| 계약 또는 청약철회 등 | **5년** |
| 대금결제 및 재화등의 공급 | **5년** |
| 소비자 불만 또는 분쟁처리 | **3년** |

**소비자가 개인정보 이용 동의를 철회해도 이 기록은 보존할 수 있습니다.**

> 2026년 10월 기준으로 확인했습니다. 시행 전 조문 재확인이 필요합니다 (`99` 참조).

**좌석 배치도를 지우면 안 됩니다.** 주최자가 다음 행사에서 재사용해야 하는데, 매번 다시 그리게 하면 안 씁니다. 행사 복제 기능도 여기에 의존합니다 (`04` 참조).

**재사용은 복제로만 합니다.** 여러 행사가 도면 하나를 같이 쓰지 않습니다. 같이 쓰면 올해 도면을 고칠 때 작년 예매 내역의 좌석 번호가 바뀝니다 (`02` 참조).

### 화면에서 내리는 것과 지우는 것은 다릅니다

끝난 행사는 관객 화면에서 "지난 예매"로 내려가지만 **데이터는 보존**됩니다. 공연이 끝난 뒤 분쟁이 생기거나 "작년에 얼마 썼나"를 확인할 일이 있습니다.

**회원 탈퇴 시**에만 soft delete가 필요합니다. 법정 보존 대상인 결제 기록은 남기고 개인 식별 정보를 분리합니다.

### 법정 보존 기간이 지나면

5년이 지나면 **누가 샀는지를 지우고 무엇이 팔렸는지만 남깁니다.**

| 지움 | 남김 |
|---|---|
| 관객 계정과의 연결 | 금액 · 좌석 · 회차 · 할인 |
| 예매자 이름 · 연락처 · 생년월일 | 취소 시각 · 사유 |
| | 판매 · 환불 · 입장률 집계 |

주최자가 보는 판매 현황과 통계는 그대로입니다. 관객의 예매 내역에서는 그때 사라집니다. **회원 탈퇴 때 하는 처리와 같은 방식**입니다.

## 대표가 바뀔 때

**소유자를 넘기면 끝**입니다. 관리자를 거치지 않습니다 (`01` 참조).

- 받을 사람은 **이미 운영자**여야 합니다. 바깥 사람이면 먼저 운영자로 초대합니다
- 넘기면 운영자 전원과 관리자에게 알림이 갑니다

**소유자와 연락이 끊긴 경우**에만 운영자가 관리자에게 이전을 신청합니다. 관리자는 주최자 신청 때 받은 연락처와 SNS 등으로 확인한 뒤 소유자를 바꿉니다. 바뀐 뒤 정산 계좌를 바꾸려면 역시 관리자 확인을 거칩니다.

> 처음에는 "주최자 계정 하나 + 관리자에게 이메일 변경 신청"이었으나, 운영진 구조(소유자·운영자)를 넣으면서 소유자 넘기기로 바뀌었고 관리자 이전은 비상 수단으로 남았습니다.
